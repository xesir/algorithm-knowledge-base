## 算法原理

**一句话结论**：把「一堆彼此独立的布尔状态」按位打包进机器字，让原本逐个处理的循环变成一次整字并行的位运算，常数缩小约一个字长（通常 $64$）。

**判断能不能用**：同时满足下面三条才值得上 bitset——

1. 每个状态只有**两种取值**（可达/不可达、存在/不存在、奇/偶）；
2. 转移是**逐元素**的布尔运算（`|`、`&`、`^`），并且常常伴随一个**整体偏移**（对应「选了这个物品后状态整体移动」）；
3. 状态总量与位宽的乘积**足够大**（一般 $n \ge 10^3$ 量级），否则打包带来的开销比省下的还多。

把整体偏移写成移位、把逐元素合并写成按位或，就得到了 OI 里几乎所有 bitset 优化的统一形态：

$$dp \mathrel{|}= (dp \ll w)$$

左边是「原来的状态集合」，右边是「作出这次选择后到达的状态集合」。这一行就是下面所有 trick 的母版。

具体的 Floyd 传递闭包案例见 [bitset 优化](basic-bitset)，本篇负责讲通法与各种变体。

## 语法速查

### `std::bitset`：定长位集

`std::bitset<N>` 是**长度在编译期固定**的 0/1 序列，每个元素只占 1 bit，`&` `|` `^` `~` `<<` `>>` 以整字为单位并行执行。

```cpp
#include <bitset>
bitset<N> bs;                  // N 必须是编译期常量
bitset<N> bs(0);               // 全 0（默认）
bitset<N> bs(0x0f);            // 用 unsigned long 初始化
bitset<N> bs(string("1010"));  // 用 0/1 字符串初始化
```

| 类别 | 用法 | 说明 |
|---|---|---|
| 访问 | `bs[pos]` | 第 `pos` 位的引用，可读可写，**不检查越界** |
| 访问 | `bs.test(pos)` | 第 `pos` 位是否为 1，越界抛 `out_of_range` |
| 容量 | `bs.size()` | 返回 `N` |
| 统计 | `bs.count()` | 置位个数，$O(N/64)$ |
| 状态 | `bs.any()` / `bs.none()` / `bs.all()` | 是否存在 1 / 是否全 0 / 是否全 1 |
| 修改 | `bs.set()` / `bs.reset()` / `bs.flip()` | 全置 1 / 全置 0 / 全体取反 |
| 修改 | `bs.set(pos)` / `bs.set(pos, val)` | 单点置 1 / 单点置为 `val` |
| 修改 | `bs.reset(pos)` / `bs.flip(pos)` | 单点置 0 / 单点取反 |
| 运算 | 按位与、按位或、按位异或、按位取反 | 返回新的 bitset |
| 移位 | `bs << k` / `bs >> k` | 整体移位，空出的位补 0 |
| 转换 | `bs.to_string()` / `bs.to_ulong()` / `bs.to_ullong()` | 转字符串 / 无符号整数 |

位运算与复合赋值的完整写法：

```cpp
a & b;   a | b;   a ^ b;   ~a;
a << k;  a >> k;
a &= b;  a |= b;  a ^= b;  a <<= k;  a >>= k;
```

**竞赛要点**：一次位运算的实际耗时约为 $O(N/w)$（$w$ 为机器字长），$N$ 在 $10^4\sim10^5$ 时远快于手写循环。典型用法就是把布尔型 DP 数组压成 bitset 做整体转移。

### `std::list`：双向链表（OI 中基本不用）

```cpp
#include <list>
list<int> lt;

lt.front(); lt.back();          // 首/尾元素，没有 lt[pos]
lt.push_front(x); lt.push_back(x);
lt.pop_front();  lt.pop_back();
lt.insert(pos, x);  lt.erase(pos);
lt.clear(); lt.empty(); lt.size();

lt.sort();                      // 链表自带排序，不能用 std::sort
lt.merge(other);                // 合并两个有序链表
lt.splice(pos, other);          // 把 other 的节点剪到 pos 前，不拷贝
lt.remove(x);                   // 删除所有值为 x 的元素
lt.unique();                    // 删除相邻重复元素
```

语法是完整的，但竞赛里几乎不用，原因有三：

1. **缓存局部性极差**。节点在堆上逐个分配、地址不连续，遍历时每次都可能是缓存未命中；`vector` 能连续预取，实测通常全面更快。
2. **每个节点都有额外开销**。除了数据本身还要存前驱/后继指针和堆的管理信息，每次插入删除都是一次 `new`/`delete`，单次常数远大于数组下标移动。
3. **有更好的替代**。真需要链表结构时（邻接表、可持久化、需要精细控制节点关系），标准做法是**数组模拟静态链表**：开 `e[N]`、`ne[N]`（必要时加 `pre[N]`），用下标代替指针，没有动态分配、内存可控、行为可预测。

一句话：`list` 的 $O(1)$ 插入在纸面上成立，但在卡常语境下换不来实际收益；这和我们用数组模拟 `stack`、`queue` 是同一个道理。

## 一般处理方式

把一段朴素代码改造成 bitset 版本，固定走这三步：

1. **找到最内层的「逐元素布尔赋值」**。典型形态是 `a[j] |= b[j - k]`、`g[i][j] |= g[k][j]`、`ok[j] = ok[j] || ok[j - w]`。
2. **把它读成「整段与整段之间的位运算」**。`j` 这一维整体消失，变成 bitset 的下标；`b[j-k]` 变成 `b << k`；逐元素或变成整行 `|`。
3. **换算复杂度判断值不值**。原来是 $O(nm)$，现在约 $O(nm/64)$。当 $m<64$ 或总运算量本来就小，直接写朴素版更快；当 $n\cdot m$ 达到 $10^8$ 以上，bitset 的收益才明显。

改造时有两个细节容易被忽略：

- **偏移方向**。`dp |= dp << w` 表示「加上 $w$」；如果状态是「剩余容量」这类反向定义，就要用右移。
- **边界截断**。超出上限的位会自动溢出丢弃，这通常是好事（相当于自动过滤非法状态），但要确认题目没有「溢出后回到合法范围」的语义。

## 常见 trick

### 1. 布尔可达性 / 可行性背包

`dp[j]` 表示容量 `j` 是否可达，标量转移是 `dp[j] |= dp[j-w]`，bitset 版一行：

```cpp
dp |= (dp << w);
```

- **多重背包**：每种物品有数量上限，做二进制拆分后对每个 0/1 物品重复上面的式子。
- **恰好用 $k$ 个**：开 `dp[k]` 数组，转移是 `dp[t] |= dp[t-1] << w`，注意要从大到小更新避免重复使用。
- **需要输出方案**：bitset 只记可行性，回溯要另存「每个状态是否由当前物品转移而来」，通常退化成 `vector` + 记录前驱。

### 2. 图上的传递闭包与可达性

- **Floyd 传递闭包**：把邻接矩阵每行压成 bitset，`if (g[i][k]) g[i] |= g[k];`，复杂度 $O(n^3/64)$。
- **DAG 拓扑传播**：按拓扑序逆序处理，`reach[u]` 初值为只有自己，对每条出边 `reach[u] |= reach[v]`，总复杂度 $O(En/64)$；稀疏图上非常划算。
- **有环图**：先 Tarjan 缩点成 DAG 再传播，SCC 内部共享同一个可达集，避免在环上反复迭代。

### 3. 高维偏序

统计「每一维都不超过我」的元素个数：给每个元素 $i$ 开一个 `bitset ans[i]`，逐维处理时把元素按该维排序、维护一个「当前维不超过我」的 `cur`，执行 `ans[i] &= cur`。结束时 `ans[i].count()` 就是答案。

总复杂度约 $O(d n^2/64)$，空间 $O(n^2/8)$ 字节。$n>5000$ 时空间会爆，标准做法是**分块**：每次只处理 $B$ 个元素，把 `bitset` 的宽度压到 $B$，用时间换空间。

### 4. 布尔矩阵乘法

布尔半环下（乘法是 `&`、加法是 `|`），$C[i][j]$ 等于「$A$ 的第 $i$ 行与 $B$ 的第 $j$ 列按位与非零」。`std::bitset` 没有列访问，所以通常**先把 $B$ 转置**，让每一列也是连续的 bitset。复杂度 $O(n^3/64)$。

如果只关心「与之后是否非零」，可以用 `(a & b).any()`；如果要统计个数，用 `count()`，但注意它在循环里是 $O(n/64)$ 的。

### 5. 莫队维护权值存在性

把当前区间的权值集合压成 bitset，`add`/`remove` 就是单点置 1/置 0。想要统计「区间内有多少种权值」时，`count()` 是 $O(V/64)$，比树状数组的 $O(\log V)$ 单点更新慢，所以**只在需要整段位运算时才有优势**（例如配合异或、平移判断）。

若存在重复权值，常用做法是把「离散化权值 + 出现次数」编码进下标来区分同一个值的不同出现。

### 6. 加速 LCS

最长公共子序列的标量 DP 是 $O(nm)$，用 bitset 可以做到 $O(nm/64)$。记 `S` 中每个字符出现的位置集合 `ch[c]`，扫描 `T` 的每个字符做一次「进位加法」：

```cpp
bitset<N> x, y;
for (char c : T) {
    x = ch[c] | pre;
    pre = (pre << 1) | 1;
    y = x & ~(x - (pre << 1));
    pre = x ^ (x + y);
}
// 最终 pre.count() 就是 LCS 长度
```

这是「用位运算模拟加法进位」的经典操作，理解不了细节也没关系，记住**LCS 也能位并行**即可。

### 7. 位并行 BFS / 距离分层

邻接矩阵的每一行压成 bitset 后，「下一步能到达哪些点」就是 `nxt |= adj[v]`（$v$ 是当前层的所有点）。每一层对整行做一次或运算，复杂度从 $O(\sum \text{deg})$ 降到 $O(n^2/64)$；对**稠密图**（如 $n\le2000$ 且边很多）反而更快。

### 8. 子树 / 集合合并

把每个点的「子树内出现的值」压成 bitset，自底向上 `bs[u] |= bs[v]`，就可以 $O(n\cdot V/64)$ 回答「子树里有哪些值」「子树内有几种值」。值域大时先离散化，或者按块分段存多个 bitset。

### 9. 区间存在性与 mex

对「下标」或「权值」建 bitset，做区间查询时把对应段的位取出、用 `(seg & mask).any()` 判断存在性。`mex` 则从低位开始找第一个 0：可以按段取反后配合 `_Find_first`（libstdc++ 扩展）快速定位。

### 10. 埃氏筛

`bitset` 存「是否为合数」，筛的时候直接 `isp |= (isp << i)` 跳过整段，比分段标记更省内存：$10^8$ 的筛法只需 12.5 MB。注意 `bitset` 的模板参数必须是编译期常量，筛上界要写成宏。

### 11. 枚举置位位置

`for (i = 0; i < N; i++) if (bs[i])` 在稀疏时是纯浪费。libstdc++ 的 `std::bitset` 提供扩展接口 `bs._Find_first()` 与 `bs._Find_next(pos)`，可以 $O(N/64)$ 地遍历所有置位位置；可移植写法是把内部字当 `uint64_t` 取出来，再配合 `__builtin_ctzll` 逐字消去最低位。

## 逐行代码解析

本篇没有完整的 `.cpp`，下面把文中反复出现的几个关键片段逐行拆开。它们就是所有 bitset 优化的「零件」。

### 母版：`dp |= (dp << w)`

```cpp
dp |= (dp << w);
```

- `dp` 是一个 `bitset<W>`，第 `j` 位为 1 表示「容量 `j` 可达」。
- `dp << w` 把每个可达状态整体右移到 `j + w`，对应「装进一个重量为 `w` 的物品」。
- `|=` 把「不装这个物品」的旧状态与新状态合并，这正是 0/1 背包「选或不选」的布尔版本。
- 整个式子等价于对 `j` 从 `W` 到 `w` 倒序执行 `dp[j] |= dp[j - w]`，但一次位运算就处理完了所有 `j`。

### Floyd：`if (g[i][k]) g[i] |= g[k];`

```cpp
if (g[i][k]) g[i] |= g[k];
```

- `g[i]` 是第 `i` 行的可达集合，`g[i][k]` 判断「$i$ 能否到 $k$」。
- 只有 `g[i][k]` 为真时，才需要把「$k$ 能到的所有点」并入第 `i` 行；这一步等价于原来的 `for (j) g[i][j] |= g[k][j]`。
- 单次是 $O(n/64)$ 的字运算，三层循环合计 $O(n^3/64)$。

### LCS：用位运算模拟进位

```cpp
x = ch[c] | pre;
pre = (pre << 1) | 1;
y = x & ~(x - (pre << 1));
pre = x ^ (x + y);
```

- `ch[c]` 是字符 `c` 在第一个串中所有出现位置的位集合。
- `x` 把「当前位置可匹配的点」与上一轮的进位状态合并。
- `y = x & ~(x - (pre << 1))` 用减法制造借位，精确定位出这一轮真正新增的匹配位置。
- 最后一行的 `x + y` 恢复进位链，`pre` 重新变成「进行中的匹配状态」。
- 扫描完第二个串后 `pre.count()` 就是 LCS 长度，整体 $O(nm/64)$。

### 语法部分：`bs.set(pos, val)` 与 `bs.test(pos)`

```cpp
bs.set(pos);        // 单点置 1
bs.set(pos, val);   // 单点置为 val
bs.reset(pos);      // 单点置 0
bs.test(pos);       // 读取，越界抛异常
```

- `set` / `reset` 是写操作，`test` 是带边界检查的读操作。
- 热路径里读单点通常用 `bs[pos]`（不检查越界，更快），只在需要防御性检查时用 `test`。
- `bs.set(pos, val)` 在需要「按条件写入」时最方便，省掉一个 `if`。

## 适用场景

**适合用**：

- 布尔可行性 DP：子集和、0/1 背包、多重背包（二进制拆分后）、「恰好用 $k$ 个」的分层背包；
- 图上的可达性：Floyd 传递闭包、DAG 拓扑传播、稠密图的逐层 BFS；
- 高维偏序统计（$n$ 在几千量级，必要时分块）；
- 布尔半环下的矩阵乘法；
- 字符串的位并行算法（LCS 一类）。

**不适合用**：

- 状态量本身很小（几百以内），打包收益抵不过开销；
- 需要输出具体方案或路径（bitset 只保留可行性）；
- 需要频繁单点查询、频繁 `count()`；
- 内存吃紧：$n$ 个长度 $n$ 的 bitset 是 $n^2/8$ 字节，$n$ 上万就要分块或换思路；
- 长度只能在运行时确定，且远超预留上限。

## 复杂度分析

单次位运算是 $O(N/64)$，这是所有分析的出发点。常见换算：

| 原始做法 | bitset 做法 |
|---|---|
| 布尔背包 $O(nW)$ | $O(nW/64)$ |
| Floyd 闭包 $O(n^3)$ | $O(n^3/64)$ |
| DAG 可达性 $O(En)$ | $O(En/64)$ |
| $d$ 维偏序 $O(dn^2)$ | $O(dn^2/64)$ |
| 布尔矩阵乘法 $O(n^3)$ | $O(n^3/64)$ |

空间上，$n$ 个长度 $n$ 的 bitset 是 $n^2/8$ 字节；$n=5000$ 时约 3 MB，$n=20000$ 时约 50 MB，再大就要考虑分块或改写。

## 常见陷阱与注意事项

- **尺寸必须是编译期常量**。`int n; cin >> n; bitset<n> b;` 编译不过。运行时长度只能用 `boost::dynamic_bitset` 或手写 `vector<uint64_t>`。
- **别在热路径反复 `count()`**。它是 $O(N/64)$，循环里调用会把收益吃光，能增量维护计数就增量维护。
- **注意栈空间**。局部 `bitset<10^8>` 约 12.5 MB，直接爆栈；改成全局或 `static`。
- **移位量不要超过位数**。`bs << k` 的 `k` 大于等于 `N` 时结果全 0，逻辑上往往等价于「非法状态」，但如果你本想回绕就必须自己处理。
- **`to_ulong()` 会溢出**。超过 `unsigned long` 宽度会抛异常，大 bitset 别用。
- **`operator[]` 不检查越界**，负下标是未定义行为。
- **`list` 不是 `bitset` 的替代品**：两者解决的是完全不同的问题，这里放在一起只是为了把 STL 语法集中交代。

## 对比与扩展

- **与 bool 数组对比**：`bool` 数组每个元素占 1 字节，bitset 占 1 bit，空间差 8 倍；时间上 bitset 还能把 $64$ 个元素的布尔运算合并成一次，差距更大。
- **与手写 `vector<uint64_t>` 对比**：思路完全一致，只是要自己算 `word = j >> 6`、`bit = j & 63`。手写的优势是**长度可以运行时决定**，劣势是要自己实现 `|=`、`count()`、移位这些操作。
- **与 bitmask DP 的区别**：状压 DP 用二进制位**编码集合状态**，改的是状态定义；bitset 优化只改变**运算方式**，状态本身仍是普通布尔数组。
- **什么时候不该用**：状态量小（$<1000$）、需要频繁单点查询、需要输出具体方案、内存不允许 $n^2/8$ 时，老老实实写标量 DP 更稳。

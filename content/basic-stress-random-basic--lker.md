## 算法原理

随机数据的生成方法有很多，这里介绍一种比较好记、也是我平时经常使用的写法。

常用的随机数种子是 `rand()`，但是它在一秒内生成的种子通常是一样的，导致一秒内运行的程序生成的随机数也可能一致。不过，绝大多数情况下暴力程序在一秒内运行不了几次，所以直接使用 `rand()` 也可以，但还是不太建议这样做。

而 `getpid()` 这个种子和系统进程有关，也就是说，每次调用时使用的种子都不一样。使用 `getpid()` 需要包含 `unistd.h` 头文件。随机数生成器使用 `mt19937`，随机数质量较高：

```cpp
mt19937 rd(getpid());
```

这样每次调用 `rd()` 就可以获得一个随机数。如果需要生成负数，进行适当的偏移即可。

如果要在区间 $[a,b]$ 内生成一个随机数，只需要使用：

```cpp
rd()%(b-a+1)+a
```

取模是为了将随机数映射到一个长度为 $b-a+1$ 的区间内，再统一加上偏移量 $a$，使其移动到合法区间。

如果要生成 $[a,b]$ 内的 $k$ 位小数，只需要先生成一个 $[a\times10^k,\,b\times10^k]$ 内的整数，再除以 $10^k$ 即可。

### 三种最常用的基础形态

| 形态 | 写法要点 |
|---|---|
| 序列 | 先定长度 $n$，再循环 $n$ 次生成每个元素 |
| 区间操作 | 随机两个端点后交换，保证左右顺序 |
| 0/1 数 | 对 $2$ 取模，按奇偶判断 |

## 逐行代码解析

下面把上面几种形态的写法逐个拆开看。

### 序列

先生成序列长度，再循环 $n$ 次生成 $n$ 个数字：

```cpp
int n=rd()%(y-x+1)+x;
for(int i=1;i<=n;i++)
    a[i]=rd()%(b-a+1)+a;
```

- 长度的范围是 $[x,y]$，元素的范围是 $[a,b]$——两组变量名别混用。
- 如果题目要求「值域很大但 $n$ 很小」，可以让元素取到 $10^9$，专门用来卡离散化、卡溢出。

### 区间操作

先随机生成两个数字，再将它们的大小交换。与先固定生成一个端点相比，这样可以使询问分布更加均匀：

```cpp
int l=rd()%(n-1+1)+1;
int r=rd()%(n-1+1)+1;
if(l>r) swap(l,r);
```

- 两个端点都独立随机，再 `swap` 归一化，比「先定 $l$、再在 $[l,n]$ 里取 $r$」分布更均匀。
- 写成 `rd()%(n-1+1)+1` 就是把上下界直接代入公式，不容易算错。

### 0/1 数

对 $2$ 取模，并根据奇偶性判断：

```cpp
int a=rd()%2?1:0;
```

- 这种写法适合生成「选或不选」的决策序列、黑白染色、布尔矩阵。
- 如果 0 和 1 的比例需要控制，可以改成 `rd()%10<3` 这种阈值写法。

### 字符串

生成一个随机数字，并将其映射到 $[0,25]$，再转化为小写字母：

```cpp
for(int i=1;i<=n;i++)
    cout<<abs(rd()%26)+'a';
```

- `rd()%26` 落在 $[0,25]$，加上 `'a'` 就得到 `a`～`z`。
- 想只从几个字符里选（比如括号序列题只允许 `(`、`)`、`*`），就改成在字符表里按随机下标取。
- 想造「大量相同字符」的极端数据，就让取值集中到少数几个字母上。

### $k$ 位小数

先放大成整数，再除回去：

```cpp
int v=rd()%(b*pow10-a*pow10+1)+a*pow10;
printf("%.3f\n", v/1000.0);
```

- 先生成 $[a\times10^k, b\times10^k]$ 的整数，再除以 $10^k$，这样小数位是「精确」的 $k$ 位。
- 直接 `rd()%b + (double)rd()/RAND_MAX` 容易踩到精度坑，不如整数化。

## 复杂度分析

生成 $n$ 个数据是 $O(n)$，空间取决于是否先存下来——边算边输出可以做到 $O(1)$。`mt19937` 单次调用是常数时间，不会成为瓶颈。

## 适用场景

- 写 `data.cpp` 时的通用底座：先有「随机整数 / 随机区间 / 随机 0-1」这三件，再往上拼具体结构。
- 需要「每次运行种子都不同」的对拍场景。
- 生成小数、坐标、权值等数值型数据。

## 常见陷阱

- **`getpid()` 是 Linux 专有**：Windows 下要 `#include <windows.h>` 用 `GetCurrentProcessId()`，或者退回 `chrono::steady_clock::now().time_since_epoch().count()`。交题环境是 NOI Linux，本地对拍要注意区分。
- **`rd()%n` 的取模偏差**：`mt19937` 的值域是 $[0,2^{32})$，对不是 $2$ 的幂的 $n$ 取模会有极微小的偏差。对拍场景完全无所谓，但写正式随机化算法时要知道这一点。
- **区间写反**：`rd()%(b-a+1)+a` 里若 $b<a$，`b-a+1` 可能为负，结果是未定义行为。
- **忘记加偏移**：只写 `rd()%(b-a+1)` 得到的是 $[0,b-a]$，不是 $[a,b]$。
- **元素范围与题目约束不一致**：比如题目保证 $a_i\ge1$，生成器却造出 $0$，两边程序都可能 UB，拍出来的结果没有意义。
- **一次生成太多**：数据量超过被测程序的处理能力时会 TLE，看起来像「死循环」，其实是数据造太大。

## 对比与扩展

- 与「树 / 图的随机生成」配合：先用这里的整数与区间套路定好参数，再套具体结构的生成模板。
- 想要更强的随机性可以用 `mt19937_64`；想要可复现的随机，就固定一个常量种子。
- 对拍时建议把「小数据 + 边界数据 + 大数据」分开生成，边界往往比随机更能打出错。

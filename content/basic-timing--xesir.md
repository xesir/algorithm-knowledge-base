## 算法原理

有时候你想知道自己的代码到底跑了多长时间，又懒得把代码丢到 OJ 上测——那就用 `clock()` 直接在本机量。

它的原理很朴素：`clock()` 返回**程序启动到现在消耗的时间**（以「时钟单位」计），而 `CLOCKS_PER_SEC` 是每秒钟包含多少个这样的时钟单位。后者是个常数，所以拿时间长度的差除以它，就换算成了**秒**。

除了便于调试，它在赛场上还有个更「实战」的用途：给暴力程序上一道保险。当运行快到超时的时候，直接结束并输出当前答案，就能多骗几个点。~~awa~~

## 逐行代码解析

源笔记里的完整计时段如下（原样搬运）：

### 计时段

```cpp
double t1=clock();
//TODO你的程序内容
double t2=clock();
double ans=(t2-t1)/CLOCKS_PER_SEC;
```

- `double t1=clock();`：在待测程序**开始前**记下当前时间。
- 中间那行注释是**占位**，把要测的程序内容替换到这里。
- `double t2=clock();`：程序跑完后，再记一次时间。
- `double ans=(t2-t1)/CLOCKS_PER_SEC;`：两次之差是消耗的时钟单位数，除以 `CLOCKS_PER_SEC` 换算成秒，结果就存进 `ans`。

### 卡时骗分

把 `ans` 的上限当作「预算」，在暴力搜索 / 枚举的主循环里定期检查：

```text
每次搜索一层时，如果 (clock()-t1)/CLOCKS_PER_SEC 已超过设定的安全值，
就立刻停止搜索并输出当前找到的答案
```

- 这样即使最优解没跑完，也能把已经得到的答案交上去，不至于 TLE 到一分没有。
- 但因为输出的是「当前最优」而非真解，本质是骗分手段，只适用于暴力 / 部分分的场合。

## 复杂度分析

`clock()` 本身是 $O(1)$ 的，取时间、做除法都不改变原算法的复杂度。

- **时间复杂度**：不改动被测程序的复杂度，取决于「你的程序内容」，故**视具体实现**。
- **空间复杂度**：只多了两个 `double`，$O(1)$。

## 适用场景

- **本地调试、对拍**：快速确认一段代码或一组数据的耗时。
- **暴力卡时骗分**：赛场上给搜索 / 枚举型暴力加一个时间上限，尽量多拿部分分。
- **估算常数**：同一算法不同写法，跑同一份数据对比耗时，选出常数更小的实现。

## 常见陷阱与注意事项

1. **`clock()` 量的是 CPU 时间**：它统计的是程序占用 CPU 的时间，和挂钟上流逝的时间不完全一样（比如程序阻塞等待时会「不计入」），所以和你在任务管理器里看到的时间可能对不上。
2. **单位要靠 `CLOCKS_PER_SEC` 换算**：它是个平台相关的常数（POSIX 上通常为 $10^6$），不要想当然当成 1000。
3. **精度有限**：在部分环境里 `clock()` 的分辨率较低，测极短程序误差会很大，多跑几遍 / 加大数据量更靠谱。
4. **别把卡时逻辑留在正式提交里**：骗分用的时间判断一旦触发会提前结束、输出不完整，正解程序必须去掉它。
5. **交互题慎用**：交互题里时间花在通信等待上，`clock()` 量到的 CPU 时间参考价值有限。

## 对比与扩展

| 工具 | 头文件 | 量的是 | 特点 |
|---|---|---|---|
| `clock()` / `CLOCKS_PER_SEC` | `<ctime>` | CPU 时间 | 简单，单位需换算，精度一般 |
| `time()` | `<ctime>` | 挂钟时间（秒级） | 精度低（秒），适合粗测 |
| `std::chrono::steady_clock` | `<chrono>` | 单调挂钟时间 | C++11 起，精度高，推荐 |
| `gettimeofday` / `std::chrono::system_clock` | `<sys/time.h>` / `<chrono>` | 系统时间 | 高精度，写法略繁琐 |

扩展方向：真要精确测时，C++11 之后优先用 `std::chrono`；而对拍、卡时这类脚本化操作，往往配合 `tools/stress.cmd` 之类的对拍流程一起用。

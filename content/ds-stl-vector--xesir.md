## 算法原理

`vector` 是序列式容器里最常用的一个，你可以粗糙地理解成「一个会自动变长的数组」：底层是一片**连续内存**，元素挨着元素排排坐。连续带来两个好处——`v[i]` 直接按地址算出，随机访问 $O(1)$；遍历时按内存顺序跑，CPU 缓存吃得香。

它有两把刷子（性质）：

1. 可以**动态分配内存**：装满了就再开一块更大的、把老元素搬过去，不用你自己算长度。
2. 重写了比较运算符及赋值运算符：`==`、`<`、`=` 这类可以直接怼整个容器。

它写在 `#include<vector>` 里，声明也是一行：

```
vector<type> v;
```

`type` 是元素类型，下文「食用方法」统一拿 `int` 演示。注意有个容易搞混的点：**长度**（`size()`，实际存了几个）和**容量**（`capacity()`，已经分配了几个位置）不是一回事，前者永远不超过后者。

## 核心公式 / 状态定义与转移方程

vector 不是动态规划结构，没有状态转移方程；它值得记的是「扩容」和「均摊代价」的关系。

假设每次装不下就翻倍扩容（扩容因子 $c > 1$），从空开始连续 `push_back` $n$ 次。第 $k$ 次扩容要搬运约 $c^{k}$ 个旧元素，总搬运代价是等比级数：

$$
T(n) = \sum_{k} c^{k} \le \frac{c}{c-1} \cdot n = O(n)
$$

把 $O(n)$ 的总代价摊到 $n$ 次操作上，就得到人们常说的**均摊 $O(1)$**——大部分插入都是常数，偶尔那一次翻倍会是 $O(n)$，但很划算。

另外随机访问按下标直接算地址（`data()` 给出内部连续内存的首元素指针）：

$$
\text{address}(v[i]) = \text{data}() + i
$$

所以 `v[i]` 是 $O(1)$。

## 逐行代码解析

原笔记的「食用方法」按用途分了几组，下面照搬并补几句要点。都是关键片段，不要求拼成一个能 AC 的完整程序。

### 声明与创建

```cpp
// 1. 创建空vector; 常数复杂度
vector<int> v0;
// 1+. 这句话可以使得向vector中插入前3个元素时，保证常数时间复杂度
v0.reserve(3);
// 2. 创建一个初始空间为3的vector，其元素的默认值是0; 线性复杂度
vector<int> v1(3);
// 3. 创建一个初始空间为3的vector，其元素的默认值是2; 线性复杂度
vector<int> v2(3, 2);
// 4. 创建一个初始空间为3的vector，其元素的默认值是1，
// 并且使用v2的空间配置器; 线性复杂度
vector<int> v3(3, 1, v2.get_allocator());
// 5. 创建一个v2的拷贝vector v4， 其内容元素和v2一样; 线性复杂度
vector<int> v4(v2);
// 6. 创建一个v4的拷贝vector v5，其内容是{v4[1], v4[2]}; 线性复杂度
vector<int> v5(v4.begin() + 1, v4.begin() + 3);
// 7. 移动v2到新创建的vector v6，不发生拷贝; 常数复杂度; 需要 C++11
vector<int> v6(std::move(v2));  // 或者 v6 = std::move(v2);
```

- `reserve(n)` 只改容量不改长度，是提前躲开反复扩容搬家的关键。
- `(n)`、`(n, val)`、拷贝构造、区间构造都要逐个造元素，所以是线性复杂度。
- 移动构造 `std::move` 是把旧容器的内存直接「接手」过来，不拷贝，常数复杂度。

### 元素访问

```cpp
v.at(pos);	//返回容器中下标为 pos 的引用。如果数组越界抛出 std::out_of_range 类型的异常。
v[pos];		//返回容器中下标为 pos 的引用。不执行越界检查。
v.front();	//返回首元素的引用。
v.back();	//返回末尾元素的引用。
v.data();	//返回 v 内部存储数据使用的连续内存空间中首元素的指针。
```

- `at()` 和 `operator[]` 就差了「检不检查越界」：`at` 越界抛异常，`[]` 越界是未定义行为但更快。

### 与长度相关

```cpp
empty();	//返回一个 bool 值，即 v.begin() == v.end()，true 为空，false 为非空。
size();		//返回容器长度（元素数量），即 std::distance(v.begin(), v.end())。
resize(n);	//改变 vector 的长度为 n。如果 n 大于当前长度，则会补充元素，如果参数中提供了要补充的元素，则使用参数，否则使用默认值；如果 n 小于当前长度，则保留前 n 个元素，后续元素删除。
max_size();	//返回容器的最大可能长度。
```

### 与容量相关

```cpp
reserve();	//使得 vector 预留一定的内存空间，避免不必要的内存分配与拷贝。
capacity();	//返回容器的容量，即当前 vector 已经为多少个元素分配了空间。
shrink_to_fit();//使得 vector 的容量与长度一致，去除该 vector 没有用到的容量。
```

- `reserve` 动容量、`resize` 动长度，别混。
- `shrink_to_fit` 把多出来的容量还回去，想省内存时用。

### 元素增删及修改

```cpp
clear();	//清除所有元素
insert();	//支持在某个迭代器位置插入元素、可以插入多个。复杂度与 pos 距离末尾长度成线性而非常数的
erase();	//删除某个迭代器或者区间的元素，返回最后被删除的迭代器。复杂度与 insert 一致。
push_back();	//在末尾插入一个元素，均摊复杂度为 常数，最坏为线性复杂度。
pop_back();	//删除末尾元素，常数复杂度。
swap();		//与另一个容器进行交换，此操作是 常数复杂度 而非线性的。
```

- 末尾的 `push_back` / `pop_back` 是甜点区；中间的 `insert` / `erase` 要搬动后面一大串，天然是线性。

## 复杂度分析

| 操作 | 时间复杂度 | 说明 |
|---|---|---|
| 随机访问 `v[i]` / `at` / `front` / `back` / `data` | $O(1)$ | 连续内存，按地址直接算 |
| `push_back`（末尾插入） | 均摊 $O(1)$，最坏 $O(n)$ | 扩容那次最坏线性 |
| `pop_back`（末尾删除） | $O(1)$ | 只减长度 |
| `insert` / `erase`（中间） | $O(n)$ | 与操作位置到末尾的距离成正比 |
| `resize` / `reserve` / `shrink_to_fit` | $O(n)$ | 要重建或搬移元素 |
| `clear` | $O(n)$ | 逐个析构元素 |
| `swap` | $O(1)$ | 只换内部指针 |

空间复杂度 $O(n)$，实际占用看 `capacity()`，一般夹在 $n$ 和 $2n$ 之间（视扩容策略而定）。

## 适用场景

- 需要**连续内存**和 **$O(1)$ 随机访问**：普通数组的「会自动变长」替代品。
- 元素几乎只在**末尾**增删：收集答案、按顺序记录结果。
- 配合 `sort` / `lower_bound` / `upper_bound`：整体遍历、排序、二分。
- 长度事先不知道、会动态变化的数据。

反过来，**频繁在头部或中间插删**就别用 vector 了（每次 $O(n)$ 搬家），上 `deque` 或 `list` 更合适。

## 常见陷阱与注意事项

1. `size()` 和 `capacity()` 别混：前者是元素个数，后者是已分配容量，两者通常不相等。
2. 迭代器 / 指针 / 引用会因为扩容或 `insert` / `erase` / `resize` / `clear` 而失效，扩容后原来保存的地址全是悬空的。
3. `at()` 越界抛 `std::out_of_range`，`operator[]` 越界是未定义行为；竞赛里图快用 `[]`，但下标得自己保证合法。
4. `reserve(n)` 只改容量不改长度，`v[i]` 仍不可访问；`resize(n)` 才会改长度。
5. `clear()` 不释放内存：`size()` 归零但 `capacity()` 不变，真想还内存用 `shrink_to_fit()` 或和空 vector 交换。
6. `size()` 返回的是无符号的 `size_t`，`v.size() - 1` 在空容器上会下溢成很大的数，倒着循环建议写成 `for (int i = (int)v.size() - 1; i >= 0; i--)`。

## 对比与扩展

| 容器 | 底层结构 | 随机访问 | 头部/中间插入 | 内存连续 |
|---|---|---|---|---|
| `vector` | 动态数组 | $O(1)$ | $O(n)$ | 是 |
| `array` | 静态数组 | $O(1)$ | 不支持 | 是 |
| `deque` | 分段数组 | $O(1)$ | 头尾 $O(1)$，中间 $O(n)$ | 否 |
| `list` | 双向链表 | $O(n)$ | $O(1)$ | 否 |

扩展方向：`vector<vector<int>>` 可以当二维矩阵用（但每行各自分配内存，整体不连续）；`priority_queue`、`stack` 都可以拿 `vector` 当底层；理解了「翻倍扩容 + 均摊分析」之后，完全可以自己用「数组 + size/capacity」手写一个迷你版。

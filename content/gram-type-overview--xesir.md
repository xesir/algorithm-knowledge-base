## 算法原理

C++ 是一门**静态类型**语言：每个变量、每个表达式的类型在编译期就确定了，类型决定了它能存什么、占多少字节、能做哪些运算。这一篇把常见的内置类型和扩展类型整理成一张总表，顺手把容易踩的类型转换坑一起讲了。

看类型抓住两件事就行：**位宽**（决定取值范围）和**符号性**（决定正负怎么表示）。搞不清这两个，溢出和符号混用就会轮番来问候你。

## 逐行代码解析

### 整型家族

| 类型 | 说明 | 大小（常见） | 实用场景 |
|------|------|-------------|---------|
| `bool` | 布尔型变量 | 1B | 条件判断 ~~居然不是1bit~~ |
| `char` | 单字符 ASCLL 编码 | 1B | ~~我也是整型没想到吧~~ |
| `short` | 有符号 16 位整数 | 2B | 极致压内存时用 |
| `int` | 有符号 32 位整数 | 4B | 通用整数 |
| `unsigned int` | 无符号 32 位整数 | 4B | 位运算，非负计数 |
| `long long` | 有符号 64 位整数 | 8B | 大整数（$10^{18}$） |
| `unsigned long long` | 无符号 64 位整数 | 8B | 位掩码，哈希，自然溢出模值 |
| `__int128` | 128 位有符号整数 | 16B | 乘法中间结果防溢出，特大数处理 |
| `unsigned __int128` | 128 位无符号整数 | 16B | 同上，无符号版本 |

- `char` 本质是 1 字节整数，所以 `'a' + 1` 是合法的，别被它字面的样子骗了。~~它自己都没想到~~
- `long long` 约 $9\times10^{18}$，两个 $10^9$ 相乘就爆了，这类乘法中间结果记得上 `__int128`。

### 浮点型家族

| 类型 | 说明 | 大小 | 实用场景 |
|------|------|------|---------|
| `float` | 单精度浮点 | 4B | 一般不用（精度低） |
| `double` | 双精度浮点 | 8B | 浮点数默认选择 |
| `long double` | 扩展精度 | 12/16B | 高精度浮点运算（小心常数） |

- 默认选 `double` 就对了；`float` 精度太丢人，`long double` 运算慢，用之前得想清代价。

### 修饰符家族

| 类型 | 说明 | 实用场景 |
|--------|------|---------|
| `const` | 不可修改 | 函数参数只读、全局常量 |
| `constexpr` | 编译期常量 | 数组大小、模板参数、编译期计算 |
| `static` | 静态存储期 | 局部变量保留值、全局变量隐藏 |
| `extern` | 外部链接 | 跨文件共享全局变量 |
| `inline` | 内联展开 | 头文件中的短函数、减少调用开销 |
| `volatile` | 防优化 | 嵌入式/多线程（OI 中极少用） |

- `constexpr` 是「编译期就能算出来的常量」，可以当数组大小、模板参数，比 `#define` 安全。
- `static` 放进函数里能让局部变量「记住」上次的值，少写全局变量。

### 复合类型家族

| 类型 | 说明 | 实用场景 |
|---------|------|---------|
| `T*` | 指针 | 动态数组、链表、传参修改 |
| `T&` | 左值引用 | 传参避免拷贝、修改原变量 |
| `T&&` | 右值引用 | 移动语义（OI 中较少） |
| `T[]` | 数组 | 静态/动态数组 |
| `pair<T1,T2>` | 二元组 | 返回两个值、存边 |
| `tuple<T1,T2,...>` | 多元组（C++11） | 返回多个值（结构化绑定拆） |
| `function<T>` | 可调用对象包装 | 存 lambda、回调、递归 |
| `decltype(expr)` | 推导表达式类型 | 声明同类型变量 |

- 传大对象（`vector`、`string`）时用 `const T&`，避免整份拷贝。

### 函数修饰家族

| 类型 | 说明 | 实用场景 |
|---------|------|---------|
| `void` | 无返回值 | 无返回值的函数 |
| `auto` 返回 | 返回类型推导 | 模板函数、lambda |
| `->` 尾置返回 | 指定返回类型 | 返回值依赖参数类型时 |
| `noexcept` | 不抛异常 | 优化（OI 中极少） |
| `override` | 显式重写 | 继承（OI 中极少） |

- 尾置返回 `auto f(...) -> T` 用于返回类型依赖参数的模板函数。

### 类型转换

- `(type)expr`（C 风格）→ 不推荐，不安全。
- `static_cast<type>(expr)` → 常用，编译期转换。
- `dynamic_cast<type>(expr)` → 多态向下转换（OI 中极少）。
- `reinterpret_cast<type>(expr)` → 位模式重解释（慎用）。
- `const_cast<type>(expr)` → 去 `const`（慎用）。
- 一句话：能用 `static_cast` 就用它，`reinterpret_cast` / `const_cast` 属于「知道自己踩雷还偏要踩」的情况。

### 位宽类型与 size_t

- **位宽类型（C++11）**：`#include <cstdint>` 后用 `int32_t`、`int64_t`、`uint64_t`，保证固定大小。
- **`size_t`**：`sizeof` 的返回值类型，无符号整数，遍历时和 `int` 比较可能产生符号警告：

```cpp
for (int i = 0; i < (int)vec.size(); ++i)   // 显式转型，规避 size_t 与 int 比较的符号警告
```

## 复杂度分析

类型本身不产生算法复杂度，但**位宽决定了常数**：

- `bool` / `char` / `short` / `int` 的运算通常一条 CPU 指令搞定；`long long` 在 32 位平台上可能要拆成两条。
- `__int128` 是编译器软件模拟的，乘除远比 64 位慢，只能在中间结果防溢出时「用一次就下车」。
- 浮点运算里 `double` 是硬件级，`long double` 在部分平台是软件实现，慢一个量级。

选类型时「够用就行」：能 `int` 不 `long long`，能 `long long` 不 `__int128`。

## 适用场景

- 开数组、算范围时按位宽选类型：先估上界再挑 `int` / `long long` / `__int128`。
- 多值返回用 `pair` / `tuple`，存边、存点用它很顺手。
- 需要固定位宽（跨平台、位运算）时上 `int64_t` 这类位宽类型。
- 传参避免拷贝用 `const T&`，要修改原值用 `T&`。

## 常见陷阱与注意事项

1. **溢出**：`int` 约 $2\times10^9$，`a*b` 里两个 `int` 相乘会先按 `int` 算再赋值，中间就爆了；乘法前先转 `long long` 或 `__int128`。
2. **符号混用**：`unsigned int a=5; int b=-1; if (a>b)` 里 `b` 会被转成无符号的巨大正数，条件为假——`unsigned` 和 `signed` 别混着比。
3. **浮点比较**：别写 `a == b`，用 `fabs(a-b) < eps`（`eps` 取 $10^{-9}$ 这类）。
4. **`size_t` 与 `int` 比较**：`size_t` 是无符号的，和负数或 `int` 比可能触发警告甚至逻辑反转，必要时显式转型。
5. **`char` 的符号性**：`char` 是否有符号由实现决定，当整数用时统一写 `signed char` / `unsigned char` 更稳。
6. **`long double` 的 printf**：得用 `%Lf`，用错格式符结果直接乱掉。

## 对比与扩展

| 需求 | 推荐类型 | 备注 |
|---|---|---|
| 通用整数 | `int` | 够用就别加长 |
| 大整数 | `long long` | 约 $9\times10^{18}$ |
| 乘法中间结果 | `__int128` | 防溢出，慢 |
| 浮点 | `double` | 默认 |
| 高精度浮点 | `long double` | 慢，慎用 |
| 固定位宽 | `int64_t` 等 | 需 `<cstdint>` |

扩展：

- **位运算配合无符号**：`unsigned` 的自然溢出在哈希、模 $2^{64}$ 场景下反而是特性。
- **`__int128` 的输入输出**：没有现成支持，通常先读字符串再手写转换，或配合快读扩展。
- **类型转换与 static_cast**：固定用 C++ 风格转换，比 C 风格更安全、也更好定位问题。

## 算法原理

学会了概念，接下来就是怎么把图存进代码里。OI 中常用的存图方式有四种，各有各的适用场景：

- **直接存边**：开一个数组，每个元素存一条边的两个端点和权值（如果有的话）。
- **邻接矩阵**：用二维数组 $\text{adj}[i][j]$ 表示从 $i$ 到 $j$ 是否有边（或者边权是多少）。
- **邻接表**：用一个 `vector` 数组，`adj[i]` 存所有从 $i$ 出发的边。
- **链式前向星**：本质上是**用单向链表实现的邻接表**，用数组模拟链表，比 `vector` 更省内存，速度也更快。

四种方式的核心取舍在于**查一条边是否存在的速度**与**空间消耗**之间的权衡，以及是否方便遍历某个点的所有出边。

## 逐行代码解析

下面把四种存图方式在笔记里的写法贴出来，重点看数据结构长什么样。

### 直接存边

开一个数组，每个元素存一条边的两个端点和权值：

```cpp
struct Edge { int u, v, w; };
vector<Edge> edges;
```

**优点**：实现简单，方便按边权排序。
**缺点**：想知道两点之间是否有边，需要遍历整个数组，$O(m)$ 效率低。
**适用场景**：Kruskal 求最小生成树。

### 邻接矩阵

用一个二维数组 `adj[n][n]`，`adj[i][j]` 表示从 $i$ 到 $j$ 是否有边（或者边权是多少）：

```cpp
int adj[N][N];  // adj[i][j] = 0 表示无边，否则存边权
```

**优点**：判断两点之间是否有边 $O(1)$，实现极其简单。
**缺点**：空间 $O(n^2)$，$n$ 稍微大一点（比如 $n > 5000$）就炸了。
**适用场景**：$n$ 较小（如 $n \le 200$）且需要频繁查询两点间边的情况，比如 Floyd 算法。

### 邻接表

用一个 `vector` 数组，`adj[i]` 存所有从 $i$ 出发的边：

```cpp
vector<pair<int, int>> adj[N];  // first 是终点，second 是边权
// 或者 vector<int> adj[N];  // 不存边权时
```

**优点**：只存储实际存在的边，空间 $O(n + m)$，适合稀疏图；可以方便地遍历一个点的所有出边。
**缺点**：判断两点之间是否有边需要遍历整个邻接表，$O(degree)$。
**适用场景**：最常用！Dijkstra、SPFA、DFS、BFS 等绝大多数场景都适用。

### 链式前向星

本质是**用数组模拟单向链表**实现的邻接表：

```cpp
struct Edge { int to, w, next; } edge[M];  // next 指向下一条边
int head[N], tot;  // head[i] 存 i 的第一条出边在 edge 中的下标

void add(int u, int v, int w) {
    edge[++tot] = {v, w, head[u]};
    head[u] = tot;
}
```

遍历从 $u$ 出发的所有边：

```cpp
for (int i = head[u]; i; i = edge[i].next) {
    int v = edge[i].to, w = edge[i].w;
    // 处理边 u -> v
}
```

**优点**：空间 $O(n + m)$，常数小，速度快，在算法竞赛中广泛使用。
**缺点**：写起来比 `vector` 麻烦。
**适用场景**：对性能要求高的题目，或者 `vector` 被卡常的时候。

## 复杂度分析

设图有 $n$ 个顶点、$m$ 条边，$d(u)$ 表示顶点 $u$ 的度数。四种方式的对比如下：

| 存储方式 | 空间 | 查边 | 遍历出边 | 适用场景 |
|---|---|---|---|---|
| 直接存边 | $O(m)$ | $O(m)$ | $O(m)$ | Kruskal 等需要直接基于边的算法 |
| 邻接矩阵 | $O(n^2)$ | $O(1)$ | $O(n)$ | $n$ 很小的全源最短路 |
| 邻接表 | $O(n+m)$ | $O(d(u))$ | $O(d(u))$ | 绝大多数情况 |
| 链式前向星 | $O(n+m)$ | $O(d(u))$ | $O(d(u))$ | 卡常、追求极致性能 |

**考场建议**：无脑上**邻接表**（`vector` 版）基本不会错。如果 $n$ 很大（比如 $10^6$）或者 `vector` 被卡常了，再换**链式前向星**。邻接矩阵只在 $n \le 200$ 且需要全源最短路时用。直接存边只在 Kruskal 时用。

## 适用场景

- **直接存边**：只需要把边拿出来排序、遍历的算法，典型是 Kruskal。
- **邻接矩阵**：$n$ 很小（大概 $n \le 200$）且要频繁查两点有没有边，例如 Floyd。
- **邻接表（`vector` 版）**：默认首选，Dijkstra、SPFA、DFS、BFS、拓扑排序都适用。
- **链式前向星**：被卡常、内存吃紧，或者边数极大时，用来替代 `vector` 版邻接表。

## 常见陷阱与注意事项

1. **邻接矩阵开不下**：$O(n^2)$ 的空间，$n > 5000$ 基本就炸了，别拿它硬刚大图。
2. **无向图要存两条边**：无向图上一条边得在两个端点各存一次，遍历时注意别把反向的那条又当成新边。
3. **自环与重边**：题目允许时要保证存图结构不会把它们吃掉；邻接矩阵天然存不了重边（会被覆盖），邻接表 / 链式前向星则可以。
4. **链式前向星的初始化**：`head` 初始化为 0、`tot` 从 0 开始，遍历写成 `for (int i = head[u]; i; i = edge[i].next)`，靠 `i` 为 0 终止，别把 0 号边也当成有效边。
5. **`vector` 被卡常**：数据量极大时 `vector` 版邻接表可能 TLE，这时候该换链式前向星。

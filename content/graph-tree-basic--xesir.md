## 算法原理

树是图论里最特殊也最重要的一类图。它不仅在算法竞赛中频繁出现，而且很多复杂图论问题（如网络流、树链剖分）的解题起点就是先把图转化成树来处理。可以说，**搞懂了树，就搞定了一半的图论**。 ~~不是你还二分上了~~

### 树的定义与性质

**定义**：树是一个**连通且无环**的无向图。

也就是说，树上任意两个顶点之间有且仅有一条简单路径。如果一棵树有 $n$ 个顶点，那么它恰好有 $n-1$ 条边。

从连通性和无环性可以推出很多重要性质：

- 树是**边数最少的连通图**（再少一条边就不连通了）。
- 树是**边数最多的无环图**（再多一条边就会出现环）。
- 任意两个顶点之间有且仅有一条简单路径（这是树最核心的性质）。
- 在树中，删去一条边会把树分成两个连通块；加一条边会产生唯一一个环。

**有根树与无根树**：如果给树指定一个特殊的顶点作为“根”，就变成了有根树。根的存在让树有了父子关系、子树、深度等概念，很多树形 DP 和算法都基于有根树。

### 树的相关概念

#### 树的遍历

遍历树是处理树问题的基本功。常见的遍历方式有：

- **深度优先遍历（DFS）**：从根（或无根树的任意点）出发，递归访问子节点。DFS 可以同时记录每个节点的父节点、深度、子树大小等。
- **广度优先遍历（BFS）**：按层逐层访问，可以用来求树的层次结构。

在 OI 中，树的遍历几乎总是用 DFS，因为它能自然地处理递归结构和子树信息。

#### 树的直径

**直径**是树上最长的简单路径的长度（或者路径本身）。求直径的经典方法：**两次 DFS**。

- 任选一个点 $s$，用 DFS 找到离它最远的点 $u$。
- 再从 $u$ 出发，找到离 $u$ 最远的点 $v$。
- 则 $u$ 到 $v$ 的路径就是树的一条直径，路径长度为 $dist(u, v)$。

为什么两次 DFS 能得到直径？可以用反证法证明：第一次找到的点 $u$ 一定是某条直径的端点。这个性质只对**树**成立。

**直径的中点**就是树的**中心**——它位于直径路径的正中间。树的中心可能是一个点或一条边（当直径长度为奇数时）。中心是树的一个“平衡点”，到所有点的最远距离最小，即最小化偏心距。

#### 树的重心

**重心**是树的一个节点，删除它后，剩下的各个连通块中，**节点数最多的那个块的大小最小**。也就是说，重心让树“尽量均匀”地分裂。

求重心的方法：

- 任选根做 DFS，计算出每个节点的子树大小 $sz[u]$。
- 对于每个节点 $u$，删除它后，最大的连通块大小为：

$$
\max_{v \in children(u)} sz[v] \quad \text{和} \quad n - sz[u]
$$

取这些值的**最小值**，对应的节点就是重心。

重心有一个重要性质：**一棵树最多有两个重心，且若有两个，它们相邻**。重心在树分治（点分治）等算法中非常关键。

### 树的特殊形态

在 OI 题目中，树有时候会以某些特殊形态出现，这些形态往往会导致不同的时间复杂度和解题策略：

- **链（Path）**：每个节点的度数最多为 2，整棵树像一条线。链上的问题常常可以转化为序列上的问题，用线段树、前缀和等处理。
- **菊花图（Star）**：有一个中心节点，其余节点都只与中心相连。这类图在贪心和 DP 中往往有简化的性质。
- **二叉树（Binary Tree）**：每个节点最多有两个子节点。树形 DP 中经常会用二叉树来降低转移复杂度，或者利用左右儿子来设计状态。
- **满二叉树 / 完全二叉树**：有特殊的平衡性质，高度 $O(\log n)$，非常适合分治和搜索剪枝。

了解这些特殊形态，可以帮助你在看到题目的树结构时快速判断是否可利用其特殊性进行优化。

### 树与搜索的关系

树本质上就是一种特殊的图，所以图上的 DFS 和 BFS 都能用在树上。但树的结构让搜索变得更简单、更高效：

1. 树上 DFS 不会遇到“重复访问”的问题（因为无环），所以不需要 visited 数组也能放心递归，只要传一个父节点防止往回走即可（对应的代码片段见下方「逐行代码解析」）。
2. 树的深度优先遍历天然具有“先处理子树，再回溯”的结构，这与树形 DP 的“自底向上”过程完美契合。
3. 树上的 BFS 可以快速计算每个节点的深度（到根的距离），这也是求最短路（边权为 1）的简单方式。

另外，搜索剪枝在树形搜索中也经常使用，比如在状态空间是树形结构时，利用当前深度和剩余可行解进行可行性剪枝。

## 逐行代码解析

上面「树与搜索的关系」里那段树上 DFS，就是本节的代码片段：

```cpp
void dfs(int x){
    //TODO
	for(auto j:G1[x]){
		if(j==fa[x]) continue;
        //TODO
		dfs(j);
        //TODO
	}	
    //TODO
    return ;
}
```

- `void dfs(int x)`：以 `x` 为当前节点出发，没有额外参数——因为树上无环，只要用 `fa[x]` 数组判断「来的那个点」即可，不需要 visited。
- `for(auto j:G1[x])`：遍历 `x` 的邻接点（`G1` 是邻接表，片段里假设它已经建好）。
- `if(j==fa[x]) continue;`：跳过父节点，防止顺着来的那条边走回去。
- `dfs(j);`：递归进子节点；`j` 与 `x` 之间的空位就是处理子树信息的位置（比如统计子树大小、更新 DP 值）。
- 几处以 `//` 开头的行内注释是笔记里保留的，分别对应「进入节点前」「处理子树后」「返回前」的时机，按题目填即可。

## 复杂度分析

树的基础操作复杂度都很低，核心原因是**每个节点、每条边都只被处理常数次**：

- **树的遍历（DFS / BFS）**：$O(n)$。$n$ 个节点各访问一次，邻接表每条边访问常数次。
- **两次 DFS 求直径**：第一次 DFS 找到最远点 $O(n)$，第二次 DFS 再找最远点 $O(n)$，合计 $O(n)$。
- **求重心**：一次 DFS 算出所有子树大小 $sz[u]$ 是 $O(n)$，再扫一遍取最小的最大块，合计 $O(n)$。
- **空间**：邻接表存储 $O(n)$（树恰好有 $n-1$ 条边），加上深度、子树大小等数组仍是 $O(n)$。

## 适用场景

- **树上路径 / 距离问题**：用直径、LCA（见下一篇）快速回答。
- **树形 DP**：利用 DFS「先子树后回溯」的结构，自底向上合并答案。
- **树分治（点分治）**：以树的重心为分割点，保证递归深度 $O(\log n)$。
- **序列化处理**：当树退化成链时，前缀和、线段树等序列工具都能直接上场。
- **判定与转化**：很多问题先证明「答案结构是一棵树」，再套用树的性质。

## 常见陷阱与注意事项

1. **无根树要自己定根**：题目没给根时，任选一个点当根，DFS 时传父节点防止走回头路。
2. **递归深度**：树退化成链时递归 DFS 深度可达 $O(n)$，$n$ 很大要开大栈或改迭代。
3. **直径性质只对树成立**：两次 DFS 求直径依赖「树无环」，换成一般图不成立。
4. **重心的判定别漏一半**：删点后最大连通块要同时考虑「各个子树」和「父亲那一侧（$n - sz[u]$）」，只算子树会漏。
5. **特殊形态先识别**：看到链 / 菊花 / 完全二叉树，先想想能不能利用形态直接把复杂度压下去。

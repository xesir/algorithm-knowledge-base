## 算法原理

虚树是用来解决**树上多组询问 DP**（尤其是**树上选点 DP**）的一把利器。核心思想一句话：**每次询问只关心少数几个「关键点」，那就别在整棵大树上来回跑了，把这些关键点单独拎出来建一棵小树，在小树上 DP。**

前置知识：**LCA**、**树形 DP**、**单调栈**。

### 问题长什么样

给定一棵 $n$ 个节点的树，边有边权。有 $q$ 次询问，每次给出一个关键点集合 $S$（大小为 $k_i$），求 $S$ 中所有点对之间距离的总和。保证 $\sum k_i \le 5 \times 10^5$，$n, q \le 10^5$。

对每个询问暴力跑一遍 $O(n)$ 的树形 DP，总复杂度 $O(nq)$，光看就过不了。但注意到每次真正在意的只有 $k_i$ 个关键点，其余节点全在陪跑——于是把这些关键点独立出来单独建树，复杂度就降到 $O(\sum k_i)$ 这一档。

### 关键点还得补上 LCA

要保证小树仍然保留原来的祖先关系，光加 $k$ 个关键点不够，还得把它们两两之间的 **LCA** 也加进去当「骨架」，用来固定关键点的相对位置。好消息是：哪怕树退化成最坏的二叉树，需要补充的节点总数也不超过 $2k-1$，所以虚树的规模始终是 $O(k)$，复杂度不会退化。

### 用单调栈建树

利用「同一子树内 dfs 序连续」的性质，可以用单调栈按 dfs 序把点一个个推进去：

1. 把关键点按 `dfn` 排序并去重。
2. 根节点先压入栈。记栈顶为 $top$，栈顶下面那个元素为 $ftop$。
3. 依次处理排序后的点 $u$，求出 $u$ 与栈顶 $top$ 的 LCA：
   - 若 $lca = top$：说明 $u$ 就在 $top$ 所在的子树里，直接把 $u$ 入栈。
   - 若 $lca \ne top$ 且 $dep[lca] < dep[ftop]$：说明 $top$ 这一支已经查完了，在虚树上连边 $ftop \to top$ 并弹出 $top$（这一步要反复做，直到条件不成立）。
   - 若 $lca \ne top$ 且 $dep[lca] \ge dep[ftop]$：说明 $lca$ 是个还没进栈的中间节点，弹出 $top$，再把 $lca$、$u$ 依次入栈（与栈顶重复的就不入）。
4. 处理完所有点后，把栈里剩下的元素依次弹出、每次连边 $ftop \to top$，虚树就建好了。

### 建完怎么 DP

拿上面那个「两两距离之和」来说：先跑一遍 DP 预处理出每个点到根的距离 $h[x]$，那么虚树上边 $u \to v$ 的边权就是 $h[v] - h[u]$。设 $v$ 子树内有 $cnt$ 个关键点，则这条边会被 $cnt \times (k - cnt)$ 对关键点跨过，贡献为 $w \times cnt \times (k - cnt)$，树形 DP 累加即可。

> 虚树没有固定模板：具体怎么连边、怎么 DP 得看题目，唯一不变的是「按 dfs 序 + 单调栈」的建树过程。

## 逐行代码解析

虚树没有统一模板，这里也不贴完整程序（`noCode`），只把「建树 + DP」的过程写成步骤伪代码。

### 模块一：关键点预处理

```cpp
sort(key + 1, key + 1 + k, cmpByDfn);          // 按原树 dfs 序排序
k = unique(key + 1, key + 1 + k) - key - 1;    // 去重
```

- 排序后相邻关键点的子树关系最接近，单调栈才能顺着 dfs 序推进。
- 去重不能省：重复的关键点会导致同一节点被反复入栈，把建树过程搞坏。

### 模块二：单调栈建树主循环

```cpp
st[++tp] = 1;                       // 根节点入栈作哨兵
for (int i = 1; i <= k; i++) {
    int u = key[i];
    int l = lca(u, st[tp]);         // u 与栈顶的 LCA
    while (tp >= 2 && dep[l] < dep[st[tp - 1]]) {
        add_edge(st[tp - 1], st[tp]);   // top 这一支查完，连边 ftop -> top
        tp--;
    }
    if (st[tp] != l) {              // l 是未进栈的中间节点，插到栈顶
        add_edge(l, st[tp]);
        st[tp] = l;
    }
    st[++tp] = u;                   // 关键点入栈
}
```

- `while` 对应「$dep[lca] < dep[ftop]$」那一支：持续弹栈连边，直到 $lca$ 落到 $top$ 与 $ftop$ 之间。
- `if (st[tp] != l)` 对应「$lca$ 是未检索到的中间节点」：先把 $l$ 与 $top$ 连边，再用 $l$ 顶替栈顶。
- 若 $lca = top$，上面两处都不触发，直接 `st[++tp] = u`，对应「$u$ 在 $top$ 子树内」的情形。

### 模块三：收尾清空栈

```cpp
while (tp >= 2) {
    add_edge(st[tp - 1], st[tp]);
    tp--;
}
```

- 处理完所有关键点后，栈里还留着一条从根到最后一个关键点的「链」，要依次弹出连边。
- 清空后栈里剩下的唯一节点就是虚树的根。

### 模块四：虚树上的树形 DP

```cpp
void dfs(int u) {
    cnt[u] = is_key[u];             // 关键点自身计数为 1
    for (auto [v, w] : V[u]) {      // V[u] 为虚树邻接表，边权 w = h[v] - h[u]
        dfs(v);
        ans += w * cnt[v] * (k - cnt[v]);
        cnt[u] += cnt[v];
    }
}
```

- 虚树边权 $w = h[v] - h[u]$ 由预处理的 $h$ 相减得到，不用再遍历原树。
- 贡献式 $w \times cnt[v] \times (k - cnt[v])$：$v$ 子树内每个关键点都要与子树外其余关键点配对，都要经过这条边。
- 自底向上汇总 `cnt`，一次 DFS 就得到所有关键点两两距离之和。

## 复杂度分析

设单次询问关键点数为 $k$，所有询问关键点总数为 $K = \sum k_i$。

- 关键点按 dfs 序排序：$O(k \log k)$
- 求 LCA：视实现而定，倍增法每次 $O(\log n)$，共 $O(k \log n)$
- 单调栈建树：$O(k)$（每个点至多入栈、出栈一次）
- 虚树上树形 DP：$O(k)$

因此单次询问总计约 $O(k \log n)$（瓶颈在 LCA），所有询问合计 $O(K \log n)$ 级别。空间上虚树本身只有 $O(k)$ 个点，大头是 LCA 的预处理数组（倍增法 $O(n \log n)$）。

由于虚树没有统一实现，frontmatter 里的复杂度记作「视具体实现」；真跑起来瓶颈通常就在 LCA 查询，建树和 DP 本身都跟 $k$ 成正比。

## 适用场景

- **树上多组询问 + 选点 DP**：每次只关心少数关键点，且 $\sum k$ 有保证，比如关键点两两距离之和、关键点集合的最小连通子树（Steiner 树）等。
- **原树固定、关键点随询问变化**：LCA 只需预处理一次，之后反复建小树，非常合适。
- 通常要**配合 LCA / 树形 DP / 单调栈**一起用，适合已经掌握树形 DP 与 LCA 的读者作为进阶工具。

**不适合**的情形：

- 单次询问就涉及整棵树（$k$ 接近 $n$）——那还不如直接在原树上跑，虚树白建。
- 树结构在询问之间频繁变化（动态加边删边）——LCA 预处理维护不动，别硬套。

## 常见陷阱与注意事项

1. **关键点必须去重**：同一关键点出现多次会导致重复入栈，建树结果错误；排序后先 `unique`。
2. **LCA 也要进虚树**：只留关键点无法构成保持祖先关系的树，必须补 LCA 当骨架；好在总数有 $2k-1$ 的上界，不会退化。
3. **排序依据是原树的 `dfn`**：不是节点编号，用错了祖先关系会错乱。
4. **区分 $top$ 与 $ftop$**：判断「这一支是否处理完」要比较 $dep[lca]$ 与 $dep[ftop]$，别跟 $dep[top]$ 比。
5. **弹栈连边方向**：连边方向是 $ftop \to top$（父指向子），反了会破坏根向结构，DP 没法自底向上。
6. **虚树边权要用原树信息换算**：压缩出来的边通常用根到点的距离之差 $h[v] - h[u]$ 表示，不能直接把原树邻接边权拼起来。
7. **DP 从虚树的根开始**：建完后根是栈里最后剩下的节点，DP 要以它自底向上汇总。
8. **别忽略 LCA 的开销**：总复杂度里 LCA 查询往往占主导，别只盯着 $O(k)$ 的建树。

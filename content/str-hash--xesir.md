## 算法原理

字符串哈希的核心思想极其朴素：**把一个字符串映射成一个整数，用整数比较代替字符串比较。**

最常用的哈希方式是**多项式哈希**。把一个字符串看作一个 $B$ 进制数：

$$
\text{hash}(s) = \sum_{i=1}^{n} s_i \cdot B^{\,n-i} \pmod{M}
$$

其中 $s_i$ 是字符的编码（比如 `a` 对应 1，`b` 对应 2），$B$ 是进制基数（通常取一个较大的质数），$M$ 是模数。

举个例子，对于字符串 `abc`，设 `a=1, b=2, c=3`，$B=131$，那么：

$$
\text{hash}(\texttt{abc}) = 1 \times 131^2 + 2 \times 131 + 3
$$

再对 $M$ 取模。这就是它的哈希值。

这样构造的哈希函数满足一个关键性质：**前缀哈希可以递推**。设 $H[i]$ 表示前 $i$ 个字符的哈希值，则：

$$
H[i] = H[i-1] \cdot B + s_i \pmod{M}
$$

这样预处理一遍，就能在 $O(1)$ 时间内得到任意前缀的哈希值。有了前缀哈希，任意子串 $s[l \dots r]$ 的哈希值也能 $O(1)$ 算出来：

$$
\text{hash}(l, r) = H[r] - H[l-1] \cdot B^{\,r-l+1} \pmod{M}
$$

所以字符哈希复杂度是预处理 $O(n)$，之后每次子串比较都是 $O(1)$。

当然，字符哈希显然也会冲突。一般我们直接开 `unsigned long long` 自然溢出，防卡也可以用双哈希。

## 核心公式 / 状态定义与转移方程

记字符串为 $s[1 \dots n]$，$s_i$ 为字符编码（建议从 1 开始，不要用 0），$B$ 为基数，$M$ 为模数。

- **哈希定义**（把串当 $B$ 进制数）：

$$
\text{hash}(s) = \sum_{i=1}^{n} s_i \cdot B^{\,n-i} \bmod M
$$

- **前缀哈希递推**（$H[0] = 0$）：

$$
H[i] = (H[i-1] \cdot B + s_i) \bmod M
$$

- **子串哈希**（$l \le r$，$B$ 的幂次预先用 $P[k] = B^k \bmod M$ 存好）：

$$
\text{hash}(l, r) = \left(H[r] - H[l-1] \cdot P[\,r-l+1\,]\right) \bmod M
$$

三个式子的分工：第一个是「哈希的定义」，第二个把定义改写成了可以 $O(1)$ 递推的形式，第三个是「高位对齐后相减」——把 $H[l-1]$ 左移 $r-l+1$ 位，让它与 $H[r]$ 的位权对齐，再做减法就把 $[1, l-1]$ 这一段的贡献消掉了。

## 逐行代码解析

源笔记这一节只给了上面三条公式，没有附代码。下面把每条公式**直译成一行 C++**，仅作公式与实现的对照，不是一份可提交的完整程序。

### 前缀哈希数组与幂次数组的预处理

```cpp
for (int i = 1; i <= n; i++) sum[i] = sum[i - 1] * B + s[i];   // 公式二：H[i] = H[i-1]*B + s[i]
for (int i = 1; i <= n; i++) P[i] = P[i - 1] * B;             // P[i] = B^i
```

- `sum[i]` 就是 $H[i]$，注意 `sum[0] = 0` 是递推的起点（`vector` 默认就全是 0）。
- `P[i]` 必须和 `sum` 一起预处理，否则子串查询时还要现算 $B$ 的幂次，$O(1)$ 就退化了。
- 用 `unsigned long long` 时不需要写 `%`，溢出即等价于对 $2^{64}$ 取模。

### 子串哈希

```cpp
unsigned long long get(int l, int r) { return sum[r] - sum[l - 1] * P[r - l + 1]; }
```

- 这就是公式三。$H[l-1]$ 乘上 $P[r-l+1]$ 后再减，是为了让两段哈希的位权对齐。
- 无符号整数相减在模 $2^{64}$ 意义下天然正确，所以不用手动补正。
- 指数是 `r - l + 1`（子串长度），写成 `r - l` 是最常见的笔误。

### 比较两个子串

```cpp
bool same(int l1, int r1, int l2, int r2) { return get(l1, r1) == get(l2, r2); }
```

- 这就是「用整数比较代替字符串比较」的落点：两次 $O(1)$ 的 `get` 加一次等号。
- 注意先判长度相等（`r1 - l1 == r2 - l2`），长度不同时虽然哈希一般也不同，但没有理论保证。

## 复杂度分析

- **时间**：预处理 `sum` 与 `P` 各一遍，$O(n)$；之后每次子串哈希、每次子串比较都是 $O(1)$。
- **空间**：前缀哈希数组与幂次数组各 $O(n)$，合计 $O(n)$。
- 换成双哈希时，时间常数与空间都翻倍，但量级不变。

## 适用场景

- **判断两个子串是否相等**：这是哈希最直接的用途，$O(1)$ 一次比较。
- **判断任意子串是否回文**：正着哈希一遍、反着哈希一遍，两侧哈希相等即为回文。
- **最长回文子串**：枚举中心 + 二分半径 + 哈希判定，$O(n \log n)$（见 Manacher 一节的「补充：哈希做法」）。
- **求 LCP / 字符串判重 / 统计不同子串个数**：配合二分与排序使用。
- **不想写 KMP 但也不需要严格线性**时，可以用哈希代替模式匹配。

## 常见陷阱与注意事项

1. **单哈希会被卡**：模数和基数都固定时，存在针对性的构造串（如 Thue–Morse 串）能让单哈希大量冲突，出题人可以卡。稳妥做法是双哈希，或随机化基数。
2. **字符编码不要取 0**：如果让 `a` 映射为 0，那么 `"a"` 与 `"aa"` 的哈希都会是 0，直接冲突。建议 `a` 映射为 1。
3. **基数和模数的选择**：基数要大于字符集大小，且最好与模数互质；模数取大质数。自然溢出时模数被固定为 $2^{64}$。
4. **无符号与有符号不要混用**：自然溢出的正确性依赖无符号类型的模 $2^{64}$ 语义，中间量一旦被当成有符号数就可能出负数。
5. **下标与指数**：子串查询里是 `sum[l - 1]`、`P[r - l + 1]`，`l - 1` 会用到 `sum[0]`，所以数组必须从下标 0 开始有效。
6. **多组数据要重算**：`P` 与 `sum` 在每组数据前都要重新初始化，否则上一组的残留会污染本组。

## 对比与扩展

| 维度 | 字符串哈希 | KMP |
|---|---|---|
| 预处理 | $O(n)$ | $O(m)$ |
| 单次子串比较 | $O(1)$ | 不适合单点比较 |
| 是否会被卡 | 单哈希可被构造数据卡 | 严格正确，无冲突 |
| 实现难度 | 低 | 中（next 数组易错） |

扩展方向：

- **双哈希**：取两组 $(B_1, M_1)$、$(B_2, M_2)$，两次哈希都相等才认为相等，冲突概率降到可忽略。
- **哈希 + 二分**：可以求 LCP、最长回文半径等「具有单调性」的量。
- **对树 / 图的哈希**：树哈希、括号序列哈希，思路同样是「给结构一个整数指纹」。

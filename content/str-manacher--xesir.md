## 算法原理

> 给定一个字符串 $s$，求它的最长连续回文子串。

### 朴素做法

回文串有两种：奇数长度（如 `aba`，中心是一个字符）和偶数长度（如 `abba`，中心是两个字符之间的空隙）。

我们可以考虑给每个字符插隔板：`a|b|b|a`。这样每种对称中心都会有一个字符对应，即全都是奇数回文，方便处理。代码里用的是 `#`：`abba` 变成 `#a#b#b#a#`，长度 $2n+1$，奇偶两种回文被强行统一成了同一种。

最朴素的做法是：枚举每个可能的中心，向两边扩展，直到不能扩展为止。复杂度 $O(n^2)$，无法接受。

注意到在朴素做法中，**每个中心都从头开始扩展，大量回文信息被重复计算**。比如字符串 `aaaaa`，枚举每个中心都要扩展一遍，总扩展次数是 $O(n^2)$。

于是 Manacher 的优化核心就是：**利用已经找到的回文串的对称性，避免重复扩展**。

### 回文半径数组

定义 $p[i]$ 为：**以位置 $i$ 为中心的最长回文串的半径**（不含中心本身）。

对于展开后的串 `#a#b#b#a#`：

| $i$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 字符 | `#` | `a` | `#` | `b` | `#` | `b` | `#` | `a` | `#` |
| $p[i]$ | 0 | 1 | 0 | 1 | 4 | 1 | 0 | 1 | 0 |

以 $i=4$ 为中心，回文串是 `#a#b#b#a#`，半径为 4。

**关键转化**：在原串中，以 $i$ 为中心的最长回文子串长度 = $p[i]$。所以**原串中最长回文子串的长度恰好等于 $\max(p[i])$**。这个「不含中心」的定义是本模板的约定，网上很多模板的半径是「含中心」的，两者差 1，右边界也要跟着差 1，别混着抄。

### 镜像对称

Manacher 的精髓在于：**利用已知回文串的对称性，直接继承一部分回文半径**。

维护两个变量：

- $C$：当前已知回文串中，**右端点最靠右**的那个回文串的中心；
- $R$：该回文串的右端点，即 $R = C + p[C]$。

当我们处理位置 $i$ 时，如果 $i < R$，说明 $i$ 在当前最右回文串的覆盖范围内。此时，$i$ 关于 $C$ 的**对称点**是 $i' = 2C - i$。

由于回文串的对称性，$p[i]$ 至少可以继承 $p[i']$ 的一部分：

$$p[i] \ge \min(p[i'],\ R - i)$$

由于 $p[i']$ 可能超出当前回文串的范围，超出部分无法保证对称性，所以取 $\min$。

**为什么能继承？** 以 $C$ 为中心、覆盖到 $R$ 的那个回文串，本身是一段左右镜像的文字。$i$ 和 $i'$ 关于 $C$ 对称，那么以 $i'$ 为中心、半径不超过 $R - i$ 的那一段回文，翻折过去就是以 $i$ 为中心、同样半径的一段回文——这段信息我们早就验证过了，不用再比。至于超出 $R$ 的部分，翻折过去落在 $R$ 左边界的更外侧，那里从来没被验证过，没有对称性可用，只能老实扩展。

还有一种情况值得单独说：如果 $p[i']$ 本身就短于 $R - i$，说明镜像点的回文根本没碰到边界，那么 $p[i]$ 就等于 $p[i']$——它俩被同一段大回文完全包住，一边扩不动，另一边也一定扩不动。

于是，Manacher 的流程是：

1. 如果 $i < R$，令 $p[i] = \min(p[2C-i], R-i)$；
2. 否则，$p[i] = 0$；
3. **暴力扩展**：从 $p[i]+1$ 开始，向两边扩展，直到不能扩展为止；
4. 更新 $C$ 和 $R$：如果 $i + p[i] > R$，令 $C = i$，$R = i + p[i]$。

## 核心公式 / 状态定义与转移方程

**状态定义**：

- $p[i]$：以展开串 $t[i]$ 为中心的回文半径，**不含中心本身**；
- $C$：当前最右回文串的中心；
- $R$：该回文串的右端点，$R = C + p[C]$（因为不含中心，右端点正好是中心加半径）；
- $ans$：过程中 $p$ 的最大值，也就是答案。

**镜像继承**：

$$p[i] = \begin{cases} \min(p[2C - i],\ R - i), & i < R \\ 0, & i \ge R \end{cases}$$

**中心扩展**（$t$ 的下标范围是 $[0, m)$）：

$$\text{while } i - p[i] - 1 \ge 0 \ \wedge\ i + p[i] + 1 < m \ \wedge\ t[i - p[i] - 1] = t[i + p[i] + 1]:\ p[i] \leftarrow p[i] + 1$$

**最右回文更新**：

$$\text{若 } i + p[i] > R:\ C \leftarrow i,\ R \leftarrow i + p[i]$$

**答案**：

$$ans = \max_i p[i]$$

## 逐行代码解析

`Untitled1--xesir.cpp` 本身是一段**主函数里的核心片段**（没有 `#include`，也没有 `main`），直接抄进自己的 `main` 里就能跑。下面拆成 3 块讲。

### 模块一：读入并插入分隔符

```cpp
string s;
cin >> s;
int n = s.size();

// 插入分隔符
string t = "#";
for (char c : s) {
    t += c;
    t += '#';
}
int m = t.size();

```

- 先读原串 $s$，长度记成 $n$。
- `t = "#"` 先放一个开头分隔符，然后每读一个字符就接「字符 + `#`」，最后自然以 `#` 收尾。所以 `abba` 变成 `#a#b#b#a#`，长度恒为 $2n+1$。
- 插入后**所有回文的中心都落在某个具体下标上**，奇数长度、偶数长度两套逻辑合并成一套，这是 Manacher 代码能这么短的前提。
- 注意 `#` 只是习惯用法，只要选一个原串里不会出现的字符就行；如果原串本身可能含 `#`（比如多组数据、字符集不固定），要换一个真正安全的哨兵字符。

### 模块二：镜像继承 + 中心扩展

```cpp
vector<int> p(m, 0);
int C = 0, R = 0;
int ans = 0;

for (int i = 0; i < m; i++) {
    // 镜像继承
    if (i < R) p[i] = min(p[2 * C - i], R - i);
    
    // 暴力扩展
    while (i - p[i] - 1 >= 0 && i + p[i] + 1 < m && t[i - p[i] - 1] == t[i + p[i] + 1])
        p[i]++;
    
```

- `p` 全部初始化为 0，`C = R = 0` 表示一开始还没有任何「已知回文」。
- `if (i < R)` 是能不能白嫖历史信息的分界线：`i` 落在当前最右回文内部才谈得上镜像，落在外面只能从 0 开始。
- `2 * C - i` 是对称点：由 $i - C = C - i'$ 反解得到 $i' = 2C - i$。
- `R - i` 是「不越过已知右边界」的保底上限，`min` 一下就把「镜像回文太长、超出已知范围」的情况截断。
- `while` 里两个越界判断都必须有：左边 `i - p[i] - 1 >= 0`、右边 `i + p[i] + 1 < m`。因为 `p[i]` 不含中心，扩展时比较的是**当前回文区间的外一格**，所以下标是 `i - p[i] - 1` 和 `i + p[i] + 1`，跟含中心模板的写法不一样。
- 继承来的半径只是下界，真正扩到不能再扩，`p[i]` 才是真实半径。

### 模块三：更新最右回文并取答案

```cpp
    // 更新最右回文串
    if (i + p[i] > R) {
        C = i;
        R = i + p[i];
    }
    
    ans = max(ans, p[i]);
}

cout << ans << '\n';
```

- `i + p[i]` 是当前回文的右端点。严格大于 `R` 才更新，等于时更新不更新都一样，`C` 换成新的也能继续用，只是没必要。
- `R = i + p[i]` 而不是 `i + p[i] - 1`：因为 `p` 不含中心，右端点就是中心加半径，减一是「含中心」模板的写法，抄错会直接把继承范围算窄一格。
- `ans = max(ans, p[i])` 取的是半径最大值，而这个值恰好等于原串最长回文子串的长度，所以直接输出 `ans` 即可，**不需要再减一**。

## 复杂度分析

看起来有一个 while 循环在暴力扩展，但实际上**每个字符最多被扩展一次**——因为每次扩展都会把 $R$ 向右推，而 $R$ 只增不减，最多从 0 推到 $2n+1$。

所以总复杂度是 $O(n)$，线性的。

细化一下这个均摊：当 $i \ge R$ 时，`p[i]` 从 0 起，每次 while 成功都会让 `i + p[i]` 越过原来的 $R$；当 $i < R$ 时，继承来的半径已经把 $[i-p[i],\ i+p[i]]$ 这一段盖住了，while 若还能成功，只能发生在 $R$ 之外，同样推着 $R$ 往右走。$R$ 单调右移、总位移 $O(n)$，所以 while 的成功次数是 $O(n)$；每次失败比对对应一轮循环，也是 $O(n)$。总时间 $O(n)$。

**空间**：展开串 `t` 长 $2n+1$，半径数组 `p` 长 $2n+1$，都是 $O(n)$，没有别的辅助结构。

## 适用场景

- **最长回文子串**：直接取 $\max(p[i])$，这是 Manacher 的主场，模板题套上就能过。
- **回文子串个数**：$\sum \lceil p[i]/2 \rceil$（每个半径对应若干个以该中心为对称轴的回文子串）。注意这个公式也是按「$p$ 不含中心」的约定推出来的。
- **判断回文串**：结合哈希可以在 $O(1)$ 判断任意子串是否为回文，但 Manacher 更适合求全局最长；若题目是大量「任意区间是否回文」的询问，正反哈希更顺手。
- **双倍回文（P4555）**：在 Manacher 基础上增加一些预处理，求两个相邻回文串拼接的最长双倍回文。
- **与其他算法拼接**：回文划分 DP 之类需要「快速判断某段是否回文」的场景，$p$ 数组配合差分可以做到 $O(1)$ 查询，比每次哈希更省常数。

### 补充：哈希做法

可以用**字符串哈希 + 二分**求最长回文子串：正着哈希一遍，反着哈希一遍，然后枚举中心，二分回文半径，用 `check` 函数 $O(1)$ 判断是否回文。

这种做法复杂度是 $O(n \log n)$，常数比 Manacher 大，但实现更简单、更通用，而且能顺便回答“任意子串是否回文”这类问题。Manacher 则是 $O(n)$，但代码细节更多，容易写挂。

两者的取舍很直白：正式比赛求最长回文，写 Manacher；只是随手判几个区间，哈希更好写也更快出结果。

## 常见陷阱与注意事项

1. **半径语义混用**：本模板 $p[i]$ 不含中心，右端点是 `i + p[i]`，答案就是 `max(p[i])`；网上大量模板的 $p[i]$ 含中心，右端点是 `i + p[i] - 1`，答案是 `max(p[i]) - 1`。两套只差常数 1，混着抄就会在边界上错得莫名其妙。
2. **扩展下标写错**：不含中心的写法比较的是 `t[i - p[i] - 1]` 和 `t[i + p[i] + 1]`；写成 `t[i - p[i]]` 与 `t[i + p[i]]` 就是含中心的写法，和继承来的 `p[i]` 语义对不上，会直接把中心字符算进半径。
3. **`i < R` 还是 `i <= R`**：写成 `i <= R` 时 `R - i` 可能是 0，继承个 0 不影响正确性，但 `2C - i` 的对称点语义在边界上已经不成立；按 `i < R` 写最稳。
4. **两个越界判断缺一不可**：只判一边，另一边就会在串首或串尾读到非法下标。本模板没有额外哨兵，全靠这两个条件兜底，删掉任何一个都可能 RE 或算出错误半径。
5. **分隔符与原串冲突**：`#` 若出现在原串里，插完就分不清哪是分隔符，回文会被错误地拉长。字符集不固定时换一个一定不出现的哨兵。
6. **更新条件写反**：必须是 `i + p[i] > R` 才更新 `C`、`R`；写成 `<` 会让最右回文不再最右，后面的继承全部作废（结果未必错，但退化成 $O(n^2)$）。
7. **忘了 `ans` 的初值**：空串讨论时 `ans = 0` 是对的；若题目保证 $n \ge 1$，`ans = 1` 起步也无妨，但不要两者混着写。
8. **多组数据不重置**：`p`、`C`、`R`、`ans` 都要在每组数据开头重新初始化。片段式代码里它们就地定义没问题，一旦提到全局复用，忘记清空就必挂。
9. **想输出子串本身**：要记下取得最大值的中心 $i$，再换算回原串下标；换算公式依赖「$p$ 是否含中心」这套约定，抄公式前先确认自己用的是哪一套。

**星图/维恩图的关键实现细节（改这块时别踩）**

- 全部纯手写 SVG，无第三方库；用 `viewBox` + `preserveAspectRatio="xMidYMid meet"`。
- 星图：`W=1040, H=760, R1=220, R2=320`；`edgePoint(a,b,shrinkA,shrinkB)` 把连线端点从圆心缩进（朝中心 50 / 朝节点 14），否则箭头会被节点圆盖住。
- 星图中心标题带**深色圆角背板**，用来挡住穿过的关联虚线；背板宽度按「汉字 19px / 其它 10.5px」估算。
- 维恩图：分类圆半径 `min(196, 74 + sqrt(题数)*23)`；环形初值 `Rx=460, Ry=225` + 220 轮轻推松弛 + 边界夹紧，保证圆不被裁。
- 维恩图 viewBox 由**内容包围盒**推出，并贴合 `#venn-body` 实际比例（`bodyAspect`，限制 1.1~2.8）；宽屏时把布局横向拉开 `kx = clamp(bodyAspect/1.5, 1, 1.55)`。
- 题目点先按「所属集合组合」分组，组内用**向日葵螺旋**铺开，再跑 80 轮全局斥力（最小 16 单位），最终最小点距约 15.9 > 直径 14。
- 分类名最后绘制并加深色背板（`rgba(7,11,24,0.72)`），保证不被点压住。
- 计算 viewBox 前必须**先 `classList.add('open')` 并填好图例**再量 `clientWidth/clientHeight`——图例会换行，高度会变。

## 3. 现在怎么加知识点 / 加题目（最新步骤）

### 3.0 输入长什么样

站主会丢**一个文件夹**，按内容判断角色（文件名不固定）：

```
任意文件夹/
├── 题目.md / 题目.txt   ← 只有题目才有
├── 代码.cpp             ← 站主本人写的实现（可能没有）
└── 思路.md / 思路.txt   ← 站主的思路总结
```

代码**逐字符搬运、不改实现**；题面**忠实转述，不补数据范围/样例**；讲解可润色扩充。

### 3.1 加知识点

1. **先 scaffold**（生成 md 骨架 + 只含任务卡注释的 .cpp + 图谱空条目）：
   ```bash
   node tools/new-kp.js --id dp-interval-stone --title "区间DP·石子合并" \
        --category 动态规划 --subcategory 区间DP --level A
   ```
2. 写 `content/<id>.md`：
   - frontmatter 必填：`id` `title` `category` `subcategory`
   - 常用可选：`tags` `timeComplexity` `spaceComplexity` `level`（A/B/C）`verified` `codePath` `noCode` `source`
   - 正文至少要有：**算法原理 / 核心公式或状态定义 / 逐行代码解析 / 适用场景 / 复杂度分析 / 常见陷阱 / 对比与扩展**
3. 代码文件放到对应分类目录，`codePath` 用**反斜杠相对路径**（如 `'动态规划\背包问题模板\01背包\标准\Untitled1.cpp'`）。
   纯讲解类知识点用 `noCode: true`，不写 `codePath`。
4. **多作者版本**：同 id 的其他人版本命名为 `content/<id>--<作者key>.md`，
   新作者要在 `build.js` 的 `AUTHOR_KEYS` 里加映射（目前：`fenfeng`→焚风、`xesir`→Xesir、`lker`→lker）。
   详情页顶部自动出现 tab，默认站主版。
5. 在 `knowledge_graph.json` 登记：`knowledgePoints[id] = { prerequisites: [...], related: [...] }`；
   新子分类还要在 `subcategories` 里加描述。`related` 必须**双向对称**，否则 lint 报 W033。
6. 跑门禁：`node tools/lint.js`（error 0）→ `node build.js`。

### 3.2 加题目

1. scaffold：
   ```bash
   node tools/new-problem.js --id prob-luogu-p1050 --title "P1050 循环" \
        --oj 洛谷 --problemId P1050 --difficulty 普及+/提高− --category 数学
   ```
   （`--difficulty` 只能填九档之一；查不到就写 `暂未评定`）
2. 写 `problems/<id>.md`：frontmatter 至少要 `id` `title` `oj` `problemId` `difficulty` `cfRating` `category` `tags` `codePath` `level` `verified` `source`。
   `cfRating` 查不到写 `NaN`，不要估。
3. 题目正文小节必须齐全（lint 会查）：
   `题目描述` → `输入格式` → `输出格式` → `数据范围` → `思路` → `代码解析` → `复杂度`
   （原文写「输入描述」要改成「输入格式」；数据范围段要独立成 `### 数据范围`，否则 W024）
4. 代码放 `题目专辑/<大类>/<题名>/代码.cpp`；作者版命名为 `代码--<作者key>.cpp`，
   md 同理为 `problems/<id>--<作者key>.md`。题目**现在支持多作者版本**（按 base id 聚合），
   没有代码时用 `#include <iostream>` 占位并注明待补。
5. 跑门禁：`node tools/lint.js` → `node build.js`。

### 3.3 修改已有内容

- 最小改动；正文里的代码块要跟着 `.cpp` 同步（lint 会比对，真漂移 0 才算过）。
- 只是「代码改了正文没改」时，只同步正文代码块，别重写整篇。

## 6. 附：本轮踩过的坑（避免重复）

| 现象 | 原因 | 解法 |
|---|---|---|
| 页面看不到改动 | `data.js` 被浏览器缓存 | Ctrl+F5 强刷 |

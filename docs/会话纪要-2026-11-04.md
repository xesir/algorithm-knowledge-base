## 3. 现在怎么加内容（本轮实测流程）

### 3.1 加题目

1. 确认三件套：题面 / 代码 / 思路；按内容判断角色，不看文件名。
2. 定元数据：`id`、`title`、`oj`、`problemId`、`difficulty`（洛谷九档）、`cfRating`、`category`、`tags`、`knowledgePoints`、`codePath`、`source`。
3. 代码原样复制到 `codePath`，不改实现。
4. 正文 8 节：题目描述（输入/输出/数据范围）、样例、解题思路、逐行代码解析、复杂度、常见陷阱、对比与扩展。
5. 跑 `node tools/lint.js`（error 0）→ `node build.js`。
6. 同步文档数量（AGENTS / PROJECT_FRAMEWORK / 提示词 / README 末尾备注）。

### 3.2 加知识点 / 作者版本

1. 先定 base：已有 base 用 `content/<base>--作者.md`；没有 base 用 `content/<new-id>--作者.md`。
2. 新作者先在 `build.js` 的 `AUTHOR_KEYS` 登记；`source` 填作者名。
3. frontmatter：`id`（= base id）、`title`、`category`、`subcategory`、`tags`、复杂度、`level`、`noCode`、`verified`、`source`。
4. 正文 7 章：算法原理 / 核心公式 / 逐行代码解析 / 复杂度 / 适用场景 / 常见陷阱 / 对比与扩展。
5. 图谱：新 base 补 `knowledgePoints` 节点与 `parent` / `prerequisites`；`related` 如添加必须双向。
6. 跑门禁、构建、同步数量。

### 3.3 拆分大讲义

1. 按一级标题/主题列清单，确定哪些是已有 base、哪些要新建。
2. 每篇只保留一个主题；原讲义的例题、代码片段归到对应篇。
3. 把 `&lt;` / `&gt;` 等 HTML 转义还原成 `<` / `>`；伪代码缩进、箭头、代码围栏统一。
4. 未完成章节按原思路补写；不要改变原结论。
5. 新 base 补图谱；新作者登记 `AUTHOR_KEYS`。
6. 门禁 → 构建 → 逐篇抽查公式/代码渲染。

## 6. 附：本轮踩过的坑

| 现象 | 原因 | 解法 |
|---|---|---|
| lint W018「行内公式 `$` 数量为奇数」 | 正文出现字面量 `$`（如“公式的 `$` 要成对”） | 改成“定界符”或转义，保证每行 `$` 成对 |
| lint W020「正文出现一级标题」 | 代码块里的 `# 注释` 被当成 Markdown 标题 | 伪代码注释改用 `//` 或缩进 |
| `dp-knapsack-topk` 的 k=0 说法不安全 | `k=0` 时 `dp[0][0]=0` 越界 | 改为“先特判 k=0 或保证 k≥1” |
| BFS 状态编码越界 | 坐标从 1 开始，`x*m+y` 最大到 `n*m+m`，`vis` 按 `n*m*4*4` 略小 | 编码改成 `((x-1)*m+(y-1))*4*4+...` |
| QOJ 中位数代码方向与正文相反 | 原文代码用 `a[i] <= x` 记 +1，正文写的是 `>= x` | 在条目里注明两种写法等价、二分方向相反 |
| 多作者默认版本切换 | build 优先站主版，否则按 `verified` 最新；同日按文件名顺序 | 需要固定默认版本时调整 `verified` 或文件名顺序 |
| README 备注插到中间 | SearchReplace 命中了旧备注的相同收尾句 | 删掉中间块，重新追加到文件末尾 |
| `更新.rar` 解压失败 | 文件是 RAR，不是 ZIP | 按备份忽略，或让用户手动解压 |
| 页面看不到新内容 | `data.js` 被浏览器缓存 | Ctrl+F5，或 URL 加 `?cb=<时间戳>` |

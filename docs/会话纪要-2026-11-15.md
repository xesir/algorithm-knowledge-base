### 1.2 前端加固（`login.html`）

- `friendlyAuthError()` 增加网络类错误分支，交给 `friendlyNetworkError()` 输出「无法连接 Supabase：项目可能已暂停，或当前网络/代理拦截了请求…」。
- 健康检查改为可中止 `fetch`（8 秒超时），失败时状态条显示「无法连接 Supabase（项目可能已暂停）· 打开控制台恢复」链接。
- 登录提交改为 `try/catch/finally`：按钮防连点，失败后恢复可点。
- `needClient(errorId)`：SDK 未加载 / 未配置时，把原因写进登录或注册表单的错误区，不再只弹一个瞬时 toast。
- `resolveLoginEmail()`：RPC 优先，失败时按 `profiles` 的 `nickname / contact / qq / luogu / cf` 反查兜底，最后回退 `AKB.contactToEmail()`。

- 选中无密码专栏：`verify_column_password(key, '')` 返回真 → 自动载入源码，并隐藏「专栏访问密码 / 验证并载入源码」整行；有密码专栏自动恢复输入区。

## 5. 通知栏（系统通知 + 聊天）

### 5.1 数据库（`supabase/phase23-notifications-chat.sql`）

| 对象 | 作用 |
|---|---|
| `public.notifications` | 站内系统通知：`user_id / kind / title / body / link / ticket_id / read_at` |
| `public.chat_messages` | 一对一文字私聊：`sender_id / recipient_id / body(1–2000) / read_at` |
| `chat_directory(p_query)` | 可聊天对象（活跃用户昵称 + 头像），因为 `profiles` 的 RLS 只允许读自己 |
| `notify_edit_ticket_owner()` + 触发器 | 新建 `type='edit'` 工单时，给目标专栏 `owner_id` 写一条通知；提交者本人是作者时不发 |

- 两表均开 RLS：通知只能读 / 标记自己的；私聊只能读自己参与的。
- 授权收紧为列级：`notifications` 只允许 `select` + `update(read_at)`；`chat_messages` 允许 `select / insert` + `update(read_at)`，不能改正文或发信人。

### 5.2 前端（`assets/notifications.js` + `assets/notifications.css`）

- 入口：右下角悬浮铃铛（与主题切换按钮错开）+ 侧边栏文字入口「🔔 通知与聊天」（首页在登录按钮上方，后台在侧边栏底部）。
- 面板：两个页签「系统通知 / 聊天」；未读角标 = 通知未读 + 私聊未读；打开系统通知即标记已读。
- 聊天：联系人列表（昵称搜索）→ 会话视图（气泡 + 时间），只支持输入文字；会话打开时每 8 秒轮询一次，关闭停止。
- 角标每 45 秒刷新一次；未登录也显示入口，面板内提示「登录后才能…」并给出去登录链接。
- 表未执行时，面板内直接提示「通知功能尚未启用：请先执行 supabase/phase23-notifications-chat.sql」，不抛错、不影响页面其它功能。

### 5.3 本轮修掉的两个前端 bug

1. `.akb-notify-badge` 的 `display:flex` 盖过 `[hidden]`，导致 0 条未读也显示一个空白红点 → 补 `.akb-notify-badge[hidden]{display:none}`。
2. 侧边栏按钮打开面板后，立刻被「点击外部关闭」逻辑关掉 → 外部触发器统一加 `data-akb-open`，关闭逻辑跳过它们。

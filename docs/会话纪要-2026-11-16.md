## 0. 一句话现状

专栏正文末尾已有「👍 点赞 / 👎 点踩 / 评分 / 💬 评论」互动区，同一专栏的所有作者版本共享；首页搜索框下新增作者、最近更新时间与「最近更新优先」排序；新评论、新点赞、新点踩都会通过站内通知告知专栏作者。点赞按 `min(n, 20) × 0.05` 小幅计入作者贡献度，点踩只参与评分、不扣分。

## 1. 专栏评论 / 点赞（phase25）

### 1.1 数据层（`supabase/phase25-column-engagement.sql`，已入库）

| 对象 | 作用 |
|---|---|
| `public.column_comments` | 评论：`column_key / user_id / author_name / content(1–500) / created_at`，索引 `(column_key, created_at desc)` |
| `column_comment_set_author()` + `trg_column_comment_set_author` | BEFORE INSERT：`btrim(content)`，用 `profiles.nickname` 覆写 `author_name`（空则「匿名用户」），前端传作者名无效 |
| `public.column_likes` | 点赞：主键 `(column_key, user_id)`，天然防重复 |
| `public.column_like_counts` | `security_invoker` 视图：`column_key + likes`，`anon` / `authenticated` 只读 |

- RLS：两表读对所有人开放；插入仅 `auth.uid() = user_id`；评论删除本人或 `is_admin()`；点赞仅本人可取消。
- 点赞数不写 `columns`：避免触发器链与并发写冲突，计数由视图汇总、前端参与贡献度计算。
- 执行结果：直连执行 25 条语句 committed；事务内验证作者名快照、`btrim`、计数后回滚。

### 1.2 前端（`index.html`）

- 互动区位于正文与代码块之后：未登录提示去登录并禁用提交；点赞可再点取消；只对自己的评论显示「删除」；用户文本全部经 `escHtml` 转义。
- `columnEngagementKey()`：`sub-*` 用自身 key，其余统一 `col-<base id>`，因此同一专栏所有作者版本共享赞 / 踩 / 评论。

## 2. 作者 / 时间检索

### 2.1 筛选栏（`#search-filters`，仅知识点模式显示）

| 控件 | 行为 |
|---|---|
| 作者 | 下拉 = `AUTHORS` + 所有版本作者，按 `resolveAuthorName` 去重，含后台上传的新作者（如 `GhostSilver`） |
| 时间 | 最近 7 / 30 / 90 / 365 天，取各版本 `published_columns.updated_at` 的最大值（`loadColumnTimes()` 全量载入） |
| 排序 | 默认顺序 / 最近更新优先（按 `kpUpdatedAt` 降序） |

- 与原有标题 / ID / 分类 / 标签 / 正文搜索叠加；命中为空显示「没有匹配的知识点」。

### 2.2 修复：数据库同步后作者下拉不刷新

- **现象**：后台上传的 `GhostSilver` 在专栏版本 tab 可见，但作者筛选下拉里没有，选不到。
- **根因**：`refreshKpAuthorOptions()` 只在 `init()` 调用一次；`loadColumnTimes()` 有一次性守卫，数据库增量同步带回新版本后没有重建下拉。
- **修复**：`refreshAfterDbSync()` 内补调 `refreshKpAuthorOptions()`。
- **验证**：Playwright 中作者下拉出现 `GhostSilver`，筛选后只剩 8 条「外培」专栏。

## 3. 点踩 / 评分 + 互动通知（phase26）

### 3.1 数据层（`supabase/phase26-column-votes-notify.sql`，已入库）

| 对象 | 作用 |
|---|---|
| `public.column_dislikes` | 点踩：主键 `(column_key, user_id)`，与点赞同构 |
| `column_vote_keep_single()` + 两个 BEFORE 触发器 | 赞 / 踩互斥：插入赞时删除同 key 的踩，反之亦然（security definer） |
| `public.column_vote_counts` | 公开视图：`likes / dislikes / rating`，`rating = round(100 × 赞 ÷ 总数)` |
| `notify_column_engagement()` + 三个 AFTER 触发器 | 新评论 / 新赞 / 新踩通知 `columns.owner_id`，`kind` 为 `column_comment` / `column_like` / `column_dislike`，链接 `index.html#<知识点 id>`，本人操作不通知 |

- 评分口径：好评率（点赞占赞 + 踩的比例），无投票时该 key 不出现在视图里，前端显示「暂无评分」。
- 点踩不扣贡献度，避免刷踩攻击；同 key 的所有作者版本共享赞 / 踩 / 评分。
- 执行结果：27 条语句 committed；事务内验证互斥、评分、三类通知与「本人操作不通知」后回滚。

### 3.2 前端（`index.html`）

- 点赞旁新增「👎 点踩」，并显示「评分 85%（12 赞 / 2 踩）」。
- 赞踩互斥与数据库一致：改票时本地同步清空另一侧计数与高亮。
- 全站计数改读 `column_vote_counts`；视图不存在时回退 `column_like_counts`（点踩按 0 计），点踩报错提示执行 phase26。
- 关键函数：`renderColumnVoteButtons()`、`toggleColumnVote(kind)`、`loadMyColumnVote()`、`loadColumnVotes()`、`columnRatingText()`。

### 3.3 通知

- 通知面板（`assets/notifications.js`）无需改动：新 `kind` 与既有系统通知共用列表与跳转逻辑。
- 通知随 45 秒轮询 / 打开面板刷新出现；点击直达对应专栏。
- 已知取舍：同一用户从赞改成踩会各发一条通知（数据库侧无法区分「改票」与「首次投票」），当前接受。

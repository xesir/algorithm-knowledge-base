## 题目描述

有 $n$ 个同学排成一列，位置为 $1 \sim n$，讲台在位置 $0$。有 $m$ 本作业堆成一摞，只能从**上往下**拿，第 $i$ 本作业属于同学 $a_i$。GOC 一次最多携带 $w$ 本作业（$w \le 5$），他可以随时回讲台取下一摞作业，沿路分发，最后不用回讲台。问发完所有作业的最短总行走距离。

## 解题思路

### 题目在问什么

一堆作业只能从上往下拿，一次最多带 $w$ 本；每趟从讲台（位置 $0$）出发沿路把作业发到同学们的位置上，可以随时回讲台补货；最后一趟发完不必回讲台。求总行走距离最小。

### 思路从哪来：看到 $w \le 5$ 就该想到状压

看到 $w \le 5$，就知道状态里可以塞下「手里拿的这几本作业分别是谁的」。

再看 $n \le 24$：每个同学编号可以用 $5$ 个二进制位存下（$2^5 = 32 > 24$），$w$ 本作业就是 $5w \le 25$ 位，刚好压进一个 `int`。两个上界一凑，这就是一道标准的**状态压缩 + 记忆化搜索**。

状态设计的关键：**手里拿的作业是哪几本，以及已经处理到第几本作业**。

### 状态定义

用 `dfs(i, state)` 表示：

- 已经处理完前 $i$ 本作业（即第 $1 \sim i$ 本已经取走或分发掉）；
- 当前手里还拿着若干本作业，这些作业对应的同学编号被压缩在 `state` 中（每本用 $5$ 位编码，按从高到低排列）；
- 返回**从当前状态开始，发完剩余所有作业所需的最短额外距离**。

编码方式：`state` 中每 $5$ 位存一个同学编号（$1 \sim n$），不足 $w$ 本时低位补 $0$。例如 `state = (x1 << 5*(w-1)) | (x2 << 5*(w-2)) | ...`，其中 $x_i$ 表示第 $i$ 本作业的目标同学。因为 $w$ 个槽位里装的其实是**一个多重集合**，代码里统一按**降序**排列后再编码，保证同一个集合只有一种编码。

因为状态空间可能很大，原笔记用 `map<int, i64>` 做记忆化。

### 转移方程

在 `dfs(i, state)` 中，先解码出当前手里各本作业的目标同学，记作数组 `x[1..w]`（空位为 $0$）。

**递归基**：如果 `i == m`，所有作业都已取走，此时只需要把手里的作业全部发掉；因为最后不用回讲台，所以代价是这些作业中最大的同学编号（走到最远的那个，沿途全都顺手发了）。即

$$
\text{ans} = \max_{1 \le j \le w} x_j
$$

（如果手里为空，则返回 $0$。）

否则，有两种决策：

1. **再拿一本新作业**（前提是手里还没满 $w$ 本）：从第 $i+1$ 本作业取走，加入手中。设当前已拿数量为 `cnt`（非零元素个数），若 `cnt < w`，则把 `a[i+1]` 放进手里再排序压缩，然后递归到 `dfs(i+1, state')`。这一趟取作业是在讲台上完成的，**不花行走距离**。

2. **发掉某一类作业**：选择当前手中存在的一个目标 $d$（即某个非零的 $x_j$），从讲台出发走到位置 $d$ 再返回讲台，代价 $2d$。走到 $d$ 的路上会经过 $1,2,\dots,d$，所以**所有目标 $\le d$ 的作业都能顺路发掉**；发完后手里只保留目标 $> d$ 的作业，递归：

$$
dfs(i, state) = \min_{d \in \text{hand}} \left( 2d + dfs(i, state_{\text{remove } \le d}) \right)
$$

   注意这里递归时 `i` 不变，因为只是发掉了手里的作业，并没有取新的作业。

最终答案就是 `dfs(0, 0)`，一开始手里没作业。

### 为什么这样设计是合法的

- 每次从讲台出发去发一批作业，回来再取下一批，符合「可以随时回讲台」的规则。
- 最后一次不用回讲台，已经在递归基中特殊处理：只取最大距离，不加返回的 $2d$。
- 拿作业的顺序被限制为从上往下，所以 `i` 单调递增，不会出现逆序。
- 因为 $w$ 很小，手里带的作业数量有限；每次发作业时把能顺路的一起发是最优的（分开跑两趟只会多走路），所以「走到 $d$ 就发掉所有 $\le d$ 的」不会漏掉更优解。

## 逐行代码解析

### 模块一：头文件与读入

```cpp
#include <bits/stdc++.h>

using i64 = long long;

void solve(void) {
    int n, m, w;
    std::cin >> n >> m >> w;
    std::vector<int> a(m + 1);
    for (int i = 1; i <= m; i++) std::cin >> a[i]; // a[i]：自上而下第 i 本作业的目标同学
```

- `i64` 是 `long long` 的别名；总距离累加可能较大，用 64 位整数。
- `a` 从 $1$ 开始编号，正好对应「第 $i$ 本」；下标 $0$ 空着不用。
- 全部逻辑收进 `solve`，方便以后改成多测。

### 模块二：编码函数、记忆化表与解码

```cpp
    auto get = [&](std::vector<int> &x) -> int { // 把 w 个目标打包进一个 int
        int res = 0;
        for (int i = 1; i <= w; i++) res |= (x[i] << (5 * (w - i)));
        return res;
    };

    std::vector<std::map<int, i64>> f(m + 1); // 按进度 i 分桶的记忆化表
    auto dfs = [&](auto && self, int i, int c) -> i64 {
        if (f[i].count(c)) return f[i][c]; // 算过就直接返回
        std::vector<int> x(w + 1);
        for (int i = 1; i <= w; i++) x[i] = (c >> (5 * (w - i))) & 31; // 解码：每 5 位取一个编号
```

- `get` 把 `x[1..w]` 从高位到低位依次摆放，每本占 $5$ 位；`& 31` 就是取低 $5$ 位（$31 = 2^5 - 1$），编码与解码严格互逆。
- `f` 按进度分桶：`f[i]` 只存「已处理到第 $i$ 本」的那些状态，避免把 $i$ 和编码混进一个键。
- 解码循环里的 `int i` **遮住了外层参数 `i`**（作用域只在这个 for 里），功能上没问题，但读代码时容易看花眼。

### 模块三：递归基与「再拿一本」

```cpp
        if (i == m) {
            return f[i][c] = *std::max_element(x.begin() + 1, x.end()); // 最后一趟只走单程
        }

        i64 ans = 1e18;
        int s = 0;
        for (int i = 1; i <= w; i++) {
            //if ((c >> (5 * i)) & 31) s++;
            if (x[i]) s++; // 统计手里现有的本数
        }

        if (s < w) {
            std::vector<int> b(w + 1);
            for (int j = 1; j <= w; j++) b[j] = x[j];
            b[s + 1] = a[i + 1]; // 新拿的一本放进第一个空位
            std::sort(b.begin() + 1, b.end(), std::greater<int>()); // 降序规范化
            ans = std::min(ans, self(self, i + 1, get(b)));
        }
```

- `i == m` 时作业全取完了，`max_element(x[1..w])` 就是「走到最远那位同学」的单程距离；手里空时最大值是 $0$。
- `s` 数的是非零槽位数。因为维护了降序，非零值一定挤在 `x[1..s]`，所以新书放到 `b[s+1]` 再排序即可。
- 降序排序是这个写法的**隐形不变量**：去重（相邻相等）和「删掉 $\le d$」都依赖它。
- `1e18` 只是「还没找到可行解」的哨兵，配合 `min` 使用。
- `//if ((c >> (5 * i)) & 31) s++;` 是留下的一行注释，位偏移写错了（多乘了一个 $5$），已经不用了。

### 模块四：发掉一批作业

```cpp
        for (int j = 1; j <= w; j++) {
            int d = x[j];
            if (d == 0) continue; // 空位跳过
            if (j > 1 && x[j] == x[j - 1]) continue; // 同一目标只枚举一次
            std::vector<int> b(w + 1);
            int idx = 1;
            for (int k = 1; k <= w; k++) {
                if (x[k] > d) b[idx++] = x[k]; // 只保留比 d 更远的，其余顺路发掉
            }
            ans = std::min(ans, (i64)2 * d + self(self, i, get(b)));
        } 

        return f[i][c] = ans;
    };
```

- `d == 0` 是空槽，跳过；`x[j] == x[j-1]` 说明这个目标已经枚举过，跳过避免重复搜索。
- `if (x[k] > d)` 保留严格大于 $d$ 的，等于 $d$ 的和更近的都被这一趟顺路发掉——这就是「走到 $d$ 沿途分发」的编码实现。
- 代价 `(i64)2 * d`：先转 64 位再乘，避免 `int` 溢出；递归时 `i` 保持不变。
- 最后 `f[i][c] = ans` 把结果写回记忆化表。

### 模块五：输出与主函数

```cpp
    std::cout << dfs(dfs, 0, 0); // 初始：一本没取、手里为空
}

int main(void) {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);

    int t = 1;
    //std::cin >> t;
    while (t--) solve();

    return 0;
}
```

- 答案就是 `dfs(0, 0)`。
- 关同步、解绑输入输出是常规加速；`t` 固定为 $1$，注释掉的那行随时可以改成多测。

## 复杂度分析

- **时间复杂度**：状态数形式上是 $O\big(m \times (n+1)^w\big)$（进度 $0\sim m$，状态是 $w$ 个 $5$ 位块），但这是很松的上界——实际可达状态远少于它：手里最多 $w$ 本、每本只能是 $1\sim n$，还要受「从上往下拿」的进度约束。单次转移需要解码 $O(w)$，发作业分支最多枚举 $w$ 个去重目标并重建状态 $O(w)$，即 $O(w^2)$。对 $m \le 1000$、$w \le 5$ 来说运行飞快。
- **空间复杂度**：$O\big(m \times (n+1)^w\big)$，即 `std::map` 记忆化表的总规模；同样受「可达状态远小于上界」的约束，实际很小。

## 常见陷阱与注意事项

1. **$5$ 位编码是用 $n \le 24$ 换来的**：$2^5 = 32 > 24$，所以每个编号刚好放得下；一旦 $n \ge 32$，编号会溢出 5 位块，压缩和解码互相污染，必须把位宽改成 $\lceil \log_2 n \rceil$ 并同步改掩码 `& 31`。
2. **降序不变量的维护**：新书是「丢到 `b[s+1]` 再整体排序」，删除分支是「只保留 $>d$ 的、按原序前移」。两处都保持降序，才有了「非零值挤在前 `s` 个槽位」和「相邻相等可去重」这两条便利；若改成乱序，`b[s+1]` 会覆盖掉有效数据。
3. **删的是 $\le d$，不是 $= d$**：这一趟走到 $d$ 会把沿途所有更近的作业一并发掉，误写成「只删等于 $d$」就会漏掉这项免费优化，答案偏大。
4. **递归基只能走单程**：`i == m` 时返回 $\max x_j$ 而不是 $2\max x_j$；忘记「最后不用回讲台」多乘个 $2$，直接 WA。
5. **拿书分支的边界**：`b[s+1] = a[i+1]` 只在 `i < m` 时执行（`i == m` 已提前返回），`s < w` 保证 `s+1 <= w` 不越界；把 `s < w` 写成 `s <= w` 就会写穿。
6. **记忆化键要带进度**：这里用 `vector<map<int,i64>> f(m+1)` 按 $i$ 分桶。若把 $i$ 和编码揉进同一个 `int` 键，两维信息可能撞车，务必分开或换成能区分两维的键。
7. **局部变量遮住外层 `i`**：解码循环和计数循环都写了 `for (int i = ...)`，和外层参数同名。C++ 里合法且不影响结果（出了 for 作用域就恢复），但极容易在改动时误伤，读代码时要看清。

## 对比与扩展

- **与旅行商 / 邮递员问题的关系**：这类「从原点出发访问若干目标求最短路」天然是 TSP 风格；但本题所有目标都在一条直线 $1\sim n$ 上，且可以反复回原点，于是「走到 $d$ 就顺路覆盖 $1..d$」这条一维几何性质，把「枚举访问顺序」的指数级搜索压成了「只决定这一趟走多远」。
- **状压 + 进度的通用套路**：当「需要保留的小集合」和「一个单调推进的进度」都能塞进状态时，就可以写成 `dfs(进度, 压缩集合)` 的记忆化搜索；「编号 $\le 2^k$ 的元素用 $k$ 位打包」这个技巧适用于任何元素编号较小的场景。
- **参数再大一点的走向**：$w \le 5$ 是状压可行的关键。若 $w$ 或 $n$ 显著增大，状态空间会爆炸，通常得换思路（例如按「最后一次回讲台」划分的区间 DP，或把往返次数建成费用流）。
- **变式**：如果要求「发完必须回到讲台」，只需把递归基的 $\max x_j$ 改成 $2\max x_j$，其余逻辑不动。

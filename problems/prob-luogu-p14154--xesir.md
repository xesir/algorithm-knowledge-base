## 题目描述

紫金山是南京的名山之一，而其中的紫金山索道曾是中国最长的吊椅式索道。游客们可以从山脚搭乘索道并一路直达山顶，总用时不超过十分钟。

为了建设索道，除了山脚和山顶的索道站，还需要沿路架设支撑塔。工程师们已经在距离索道入口 $0$ 单位距离和 $(n + 1)$ 单位距离的位置建设了索道站，并勘察了在 $1, 2, \cdots, n$ 单位距离架设支撑塔的成本，分别是 $a_1, a_2, \cdots, a_n$。

出于工程因素考虑，部分位置必须架设支撑塔。同时为了保证索道的安全性，相邻支撑塔或索道站之间的距离必须小于等于 $k$。也就是说，假设最终建设两座索道站与架设 $m$ 座支撑塔的位置为 $b_0, b_1, b_2, \cdots, b_m, b_{m + 1}$，其中 $0 \le m \le n$，$0 = b_0 < b_1 < b_2 < \cdots < b_m < b_{m + 1} = n + 1$，那么对于所有 $1 \le i \le m + 1$ 有 $b_i - b_{i - 1} \le k$。

同时，为了使建设方案更加灵活，工程师们会对成本序列进行 $q$ 次临时的修改。第 $i$ 次修改形如 $(p_i, v_i)$，意思是临时将 $a_{p_i}$ 的值修改为 $v_i$。

您需要对每次修改求出，符合以上要求的前提下，架设支撑塔的最小总成本。

请再次注意，所有修改都是临时且相互独立的。也就是说，在计算一次修改的答案之后，此次修改将会被撤销，成本序列将会恢复原来的样子。

### 输入格式

有多组测试数据。第一行输入一个整数 $T$ 表示测试数据组数，对于每组测试数据：

第一行输入两个整数 $n$ 与 $k$（$1 \le n \le 5 \times 10^5$，$1 \le k \le \min(n + 1, 3 \times 10^3)$）表示架设支撑塔的备选位置数以及相邻支撑塔或索道站之间的最大距离。

第二行输入 $n$ 个整数 $a_1, a_2, \cdots, a_n$（$1 \le a_i \le 10^9$），其中 $a_i$ 表示在 $i$ 单位距离架设支撑塔的成本。

第三行输入一个长度为 $n$ 的二进制字符串 $s_1s_2\cdots s_n$（$s_i \in \{\texttt{0}, \texttt{1}\}$）。如果 $s_i = \texttt{1}$ 则必须在 $i$ 单位距离架设支撑塔。如果 $s_i = \texttt{0}$ 则您可以决定是否在 $i$ 单位距离架设支撑塔。

第四行输入一个整数 $q$（$1 \le q \le 3 \times 10^3$）表示修改的次数。

对于接下来 $q$ 行，第 $i$ 行输入两个整数 $p_i$ 与 $v_i$（$1 \le p_i \le n$，$1 \le v_i \le 10^9$）表示第 $i$ 次修改。

### 输出格式

每次修改输出一行一个整数表示临时应用该修改后，架设支撑塔的最小总成本。

### 数据范围

保证所有数据 $n$ 之和不超过 $2 \times 10^6$。另外保证所有数据 $k$ 之和与 $q$ 之和均不超过 $10^4$。

## 解题思路

### 先去掉修改和必选：一个滑动窗口 DP

把 $0$ 和 $n+1$ 看成两个免费的、必选的「塔」（成本为 $0$）。问题变成：在 $0\sim n+1$ 里选一个子序列，包含 $0$ 和 $n+1$，相邻两项差不超过 $k$，最小化所选位置的成本和。

设 $f_i$ 表示「在 $i$ 建塔，且 $0\sim i$ 这一段已经合法」的最小成本。上一座塔 $j$ 必须在 $[i-k, i-1]$ 里：

$$f_i=a_i+\min_{j\in[i-k,\,i-1]} f_j,\qquad f_0=0$$

答案是 $f_{n+1}$（$a_{n+1}=0$）。

朴素的转移是 $O(nk)$ 的，但这是标准的**定长滑动窗口最小值**，用单调队列可以做到 $O(n)$。

### 加上必选：遇到必选就清空队列

如果 $i$ 是必选点，那么任何「$j\to i'$（$i'>i$）」的转移里，$j$ 都不可能小于 $i$——因为链必须经过 $i$，过不了 $i$ 的位置作废。

所以处理到必选点 $i$ 时：

1. 先用当前队列算出 $f_i$；
2. 然后把整个队列清空，只把 $i$ 放进去。

清空之后，后面的位置只能从 $i$ 往后选上一座塔，正好满足「必须经过 $i$」。

### 后缀 DP

由于「相邻差不超 $k$」这个约束左右对称，可以倒着再做一遍：

$$g_i=a_i+\min_{j\in[i+1,\,i+k]} g_j,\qquad g_{n+1}=0$$

$g_i$ 表示「在 $i$ 建塔，且 $i\sim n+1$ 这一段合法」的最小成本。必选点的处理方式完全对称：处理完 $g_i$ 后清空队列。

### 修改怎么处理

单点修改只影响 $k$ 邻域内的直接转移，但间接影响会一路传下去，所以不能只重算 $k$ 个 $f$。

关键在于：把答案拆成「左半边 + 右半边」。设被改的位置是 $x$，新值是 $v$。

**情况 A：$s_x=\texttt{1}$（必选）。**

$x$ 一定要建塔，$f_{n+1}$ 里已经包含了 $a_x$，所以答案就是

$$f_{n+1}-a_x+v$$

**情况 B：$x$ 不必选。** 分两种子情况：

1. **在 $x$ 建塔**：左边用 $f$、右边用 $g$，两边在 $x$ 处拼接、互不影响，代价为

$$v+\min_{i\in[\max(l,x-k),\,x-1]} f_i+\min_{j\in[x+1,\,\min(r,x+k)]} g_j$$

2. **不在 $x$ 建塔**：那就要跨过 $x$，即存在 $i<x<j$ 且 $j-i\le k$，代价为

$$\min_{i}\Big(f_i+\min_{j\in[x+1,\,\min(r,\,i+k)]} g_j\Big)$$

其中 $i$ 取 $[\max(l,x-k),\,x-1]$，且要满足 $i+k\ge x+1$。

这里的 $l$ 是 $x$ 左边最近的必选位置，$r$ 是右边最近的必选位置（$0$ 和 $n+1$ 也算必选）。

**为什么要卡 $l$ 和 $r$？** 因为 $f_i$ 只保证 $0\sim i$ 合法。如果 $i<l$，那么 $i\to x$ 这一段会跳过必选点 $l$，这个方案非法；同理 $j>r$ 会跳过 $r$。

### 情形 B2 的双指针

固定 $i$ 时，右侧要的是一段以 $x+1$ 开头、右端点随 $i$ 单调右移的区间的最小值。随着 $i$ 增大，$\min(r,i+k)$ 单调不减，所以可以用一个指针 `je` 一路向右扩展，用 `mg` 维护已经扫过部分的最小 $g$。

这样每次询问的总代价是 $O(k)$，加上预处理 $O(n)$，整体 $O(n+qk)$。

## 逐行代码解析

### 头文件与全局数组

```cpp
#include <bits/stdc++.h>
using namespace std;
#define int long long
#define PII pair<int,int>
#define fi first
#define se second
const int N=5e5+10,INF=1e18;
int a[N],dp[N],g[N],pre[N],nxt[N];
```

- `#define int long long`：$a_i$ 到 $10^9$、最多选 $5\times10^5$ 个点，总和能到 $10^{14}$，必须开 `long long`。
- `PII` 是单调队列里存的 `(下标, dp 值)`。
- `dp` 是前缀 DP，`g` 是后缀 DP；`pre[i]` / `nxt[i]` 分别是 $i$ 左右最近的必选位置。
- `INF=1e18` 作为「不可达」的哨兵。

### 前缀 DP：单调队列

```cpp
signed main(){
	ios::sync_with_stdio(0);
	cin.tie(0);cout.tie(0);
	int t;cin>>t;
	while(t--){
		int n,k,q;cin>>n>>k;
		a[0]=0;a[n+1]=0;
		for(int i=1;i<=n;i++){
			cin>>a[i];
		}
		string s;cin>>s;s='1'+s+'1';
		deque<PII> h;h.push_back({0,0});
		for(int i=1;i<=n+1;i++){
			while(h.size()&&h.front().fi<i-k) h.pop_front();
			dp[i]=h.front().se+a[i];
			if(s[i]=='1') while(h.size()) h.pop_back();
			else while(h.size()&&h.back().se>dp[i]) h.pop_back();
			h.push_back({i,dp[i]});
		}
```

- `a[0]=a[n+1]=0`：两个索道站免费且必建。
- `s='1'+s+'1'`：把下标平移到 $0\sim n+1$，同时把两头标成必选，后面统一处理。
- 队列里存 `(位置, dp 值)`，并保持 `dp` 值单调递增。
- `h.front().fi < i-k` 弹出过期的队头：第 $i$ 个位置只能从 $[i-k,i-1]$ 转移。
- 先算 `dp[i]`，再决定怎么入队：**必选点清空整个队列**（只留自己），**非必选点按单调性从队尾弹掉更差的**。
- 注意 $i=n+1$ 时也会走一遍循环，正好把 $f_{n+1}$ 算出来。

### 后缀 DP

```cpp
		while(h.size()) h.pop_back();
		g[n+1]=0;
		h.push_back({n+1,0});
		for(int i=n;i>=0;i--){
			while(h.size()&&h.front().fi>i+k) h.pop_front();
			g[i]=h.front().se+a[i];
			if(s[i]=='1') while(h.size()) h.pop_back();
			else while(h.size()&&h.back().se>g[i]) h.pop_back();
			h.push_back({i,g[i]});
		}
```

- 先清空队列复用，把 $n+1$ 作为后缀的起点（$g_{n+1}=0$）。
- 方向反过来，过期判断也反过来：`h.front().fi > i+k` 说明太远了。
- 必选处理与正向完全对称。
- 循环到 $i=0$ 结束，`g[0]` 就是「从 $0$ 一路走到 $n+1$」的代价，理论值等于 `dp[n+1]`。

### `pre` / `nxt` 预处理

```cpp
		pre[0]=0;
		for(int i=1;i<=n+1;i++){
			if(s[i]=='1') pre[i]=i;
			else pre[i]=pre[i-1];
		}
		nxt[n+1]=n+1;
		for(int i=n;i>=0;i--){
			if(s[i]=='1') nxt[i]=i;
			else nxt[i]=nxt[i+1];
		}
```

- `pre[i]`：$\le i$ 的最近必选位置；`nxt[i]`：$\ge i$ 的最近必选位置。
- 因为 $s_0$ 和 $s_{n+1}$ 都是 `'1'`，两个数组不会出现「找不到」的情况，省掉边界判断。

### 询问：必选点与「在 $x$ 建塔」

```cpp
		cin>>q;
		while(q--){
			int x,y;cin>>x>>y;
			if(s[x]=='1'){
				cout<<dp[n+1]-a[x]+y<<'\n';
				continue;
			}
			int ans=INF;
			int l=pre[x],r=nxt[x];
			int lmi=INF,rmi=INF;
			for(int i=max(l,x-k);i<=x-1;i++) lmi=min(lmi,dp[i]);
			for(int j=x+1;j<=min(r,x+k);j++) rmi=min(rmi,g[j]);
			if(lmi<INF&&rmi<INF) ans=min(ans,y+lmi+rmi);
```

- `s[x]=='1'`：必选点，直接替换成本即可，不用重跑 DP。
- `l=pre[x]`、`r=nxt[x]`：因为 $x$ 不是必选点，`pre[x]` 就是左边最近的必选点、`nxt[x]` 是右边最近的必选点。
- 左边窗口下界取 `max(l, x-k)`，右边窗口上界取 `min(r, x+k)`，两个方向互相独立。
- `lmi` / `rmi` 都是 $O(k)$ 暴力扫，因为 $k\le 3\times10^3$、$q\le 3\times10^3$，乘起来在可接受范围内。
- 三个量相加即为「在 $x$ 建塔」的答案。

### 询问：「不在 $x$ 建塔」

```cpp
			int mg=INF,je=x;
			for(int i=max(l,x-k);i<=x-1;i++){
				if(i+k<x+1) continue;
				int lim=min(r,i+k);
				while(je<lim){
					je++;
					mg=min(mg,g[je]);
				}
				if(mg<INF) ans=min(ans,dp[i]+mg);
			}
			cout<<ans<<'\n';
		}
	}
	return 0;
}
```

- `i+k<x+1` 说明左边这座塔够不到 $x$ 右边，跳过。
- `lim=min(r,i+k)`：右端点是「够得最远」和「不越过下一个必选点」的较小值。
- `je` 只向右移动，`mg` 维护 $[x+1,\text{je}]$ 上 $g$ 的最小值；由于 `lim` 单调不减，`mg` 无需回退。
- 最后 `ans` 取两种子情况的最小值输出。

## 复杂度分析

预处理 `dp`、`g`、`pre`、`nxt` 都是 $O(n)$；每次询问两段暴力扫 $O(k)$ 加一次双指针 $O(k)$，共 $O(k)$。单组总复杂度 $O(n+qk)$，空间 $O(n)$。$\sum n\le2\times10^6$、$\sum k\le10^4$、$\sum q\le10^4$ 的约束正好对应这个复杂度。

## 常见陷阱与注意事项

- **必选点要清空队列**，不是简单跳过；只清空会漏掉「链必须经过 $i$」的约束。
- **两头要标成必选**：`s='1'+s+'1'`，否则 `pre/nxt` 会越界或找不到。
- **询问时窗口要卡 $l,r$**：不卡的话会生成跳过必选点的非法方案，答案偏小。
- **`i+k<x+1` 必须跳过**：否则 $j$ 区间为空，`mg` 保持 `INF` 或残留旧值。
- **`mg` 不能回退**：`je` 只增不减，`mg` 也只对扩展部分取 min，这与双指针的正确性绑定。
- **必选点修改**用 `dp[n+1]-a[x]+y`，注意 `dp[n+1]` 里只算了一次 $a_x$。

## 对比与扩展

- 与「P7114 字符串匹配」的关系：那道题用调和级数把枚举量压到 $O(n\log n)$，本题用单调队列把 DP 压到 $O(n)$，都是「找到被重复计算的部分并一次性维护」。
- 拓展提到的 $(min,+)$ 半环矩阵做法：把「最近 $k$ 个 $f$ 的转移」写成 $k\times k$ 矩阵，用矩阵快速幂处理「查询任意区间」的场景。本题单点修改用前后缀 DP 更简单，但那个思想在 $k$ 很小、查询区间任意时非常关键。
- 「必选点分段」也是一种合法写法：把序列按必选点切成若干段分别做 DP，但代码里用清空队列更短。

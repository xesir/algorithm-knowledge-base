## 题目描述

共有 $4$ 种硬币，面值分别为 $c_1,c_2,c_3,c_4$。

某人去商店买东西，去了 $n$ 次。对于每次购买，他带了 $d_i$ 枚第 $i$ 种硬币，想购买 $s$ 的价值的东西。请问每次有多少种付款方法。

### 输入格式

输入的第一行是五个整数，分别代表 $c_1,c_2,c_3,c_4, n$。

接下来 $n$ 行，每行有五个整数，描述一次购买，分别代表 $d_1, d_2, d_3, d_4, s$。

### 输出格式

对于每次购买，输出一行一个整数代表答案。

### 数据范围

对于 $100\%$ 的数据，保证 $1 \le c_i, d_i, s \le 10^5$，$1 \le n \le 1000$。

## 样例

### 样例 1

**输入：**

```
1 2 5 10 2
3 2 3 1 10
1000 2 2 2 900
```

**输出：**

```
4
27
```

## 解题思路

题面要求的是计算满足

$$\sum_{i=1}^{4} c_i x_i = s,\qquad x_i \le d_i$$

的方案数。

「每种硬币有上限」这个约束不好直接做，考虑**补集**：先算不带上限的方案数，再减去「至少有一种硬币超限」的方案数。

用容斥原理：枚举一个集合 $S$ 表示「$S$ 里的硬币都超出上限」，其余硬币不做约束。偶加奇减就得到合法方案数。

怎么算「至少 $S$ 超限」的方案数？假设 $S$ 里的硬币都超出约束，那么对每个 $i\in S$ 有

$$x_i = d_i + 1 + cur_i,\qquad cur_i \ge 0$$

把多出来的 $c_i(d_i+1)$ 先从总价值里扣掉，剩下的部分对四种硬币都**没有上限**——相当于跑一次完全背包，取 $s-\sum_{i\in S}c_i(d_i+1)$ 处的 $dp$ 值即可。

由于 $c_i$ 固定，完全背包可以只预处理一次。总复杂度 $O(16n+s)$。

### 为什么想到补集

直接做的话，每种硬币都有一个上限 $d_i$，四维枚举显然不现实。而「上限」这类约束有一个特点：**去掉它之后问题极简单**（就是无限背包），加上它才变难。

所以走补集：先不管上限，算出「凑出 $s$ 的全部方案」，再减掉「某个硬币超额」的那些方案。

### 容斥的完整写法

设 $A_i$ 表示「第 $i$ 种硬币使用数量超过 $d_i$」的方案集合，我们要的是 $\left|\overline{A_1}\cap\overline{A_2}\cap\overline{A_3}\cap\overline{A_4}\right|$。由容斥：

$$\text{ans}=\sum_{S\subseteq\{1,2,3,4\}}(-1)^{|S|}\left|\bigcap_{i\in S}A_i\right|$$

其中 $S=\varnothing$ 那一项就是「完全无上限」的方案数。集合 $S$ 只有 $2^4=16$ 种，逐个枚举即可。

### 为什么扣掉 $c_i(d_i+1)$ 就变回无上限

固定一个 $S$，要求每个 $i\in S$ 都超额。注意「超额」只是一个下界：只要用了 $d_i+1$ 枚就一定超了，多出来的部分可以是任意多枚。所以令

$$x_i=(d_i+1)+y_i,\qquad y_i\ge 0$$

对每个 $i\in S$ 都这样替换，代回 $\sum c_ix_i=s$：

$$\sum_{i\in S}c_i(d_i+1)+\sum_{i\in S}c_iy_i+\sum_{j\notin S}c_jx_j=s$$

移项后，左边剩下的部分就是「四种硬币都无上限」的方程。于是只要先扣掉 $\sum_{i\in S}c_i(d_i+1)$，剩下价值 $s'$ 的方案数正好是预处理的完全背包值 $f[s']$。$s'<0$ 说明无解，贡献 $0$。

### 手算样例

第一组：$c=(1,2,5,10)$，$d=(3,2,3,1)$，$s=10$。

先看有哪些合法方案：

| 方案 | 是否合法 |
|---|---|
| $10\times1$（即 $10$ 枚 $1$ 元） | ✗ 超过 $d_1=3$ |
| $1+2+2+5=10$，即 $x=(1,2,1,0)$ | ✓ |
| $3+2+5=10$，即 $x=(3,1,1,0)$ | ✓ |
| $5+5=10$，即 $x=(0,0,2,0)$ | ✓ |
| $10=10$，即 $x=(0,0,0,1)$ | ✓ |

共 $4$ 种，与样例输出一致。容斥的做法会先算出全部无上限方案，再依次减掉「$1$ 元超 3 枚」「$2$ 元超 2 枚」……最后剩下的正好是上面这 $4$ 种。

## 逐行代码解析

### 头文件与全局数组

```cpp
#include <bits/stdc++.h>
using namespace std;
#define int long long
const int N=1e5+10;
int f[N],c[4],d[4];
```

- `#define int long long`：答案规模可能超过 `int`，统一开 `long long`，同时 `main` 要写成 `signed main`。
- `f[j]` 是完全背包的 DP 数组，`c[4]`、`d[4]` 分别存面值与每次购买的数量上限。
- `N=1e5+10` 对应 $s$ 的上界。

### 预处理完全背包

```cpp
signed main(){
    ios::sync_with_stdio(0);
    cin.tie(0);cout.tie(0);
    for(int i=0;i<4;i++) cin>>c[i];
    int n;cin>>n;
    f[0]=1;
    for(int i=0;i<4;i++){
        for(int j=0;j<N;j++){
            if(j-c[i]>=0) f[j]+=f[j-c[i]];
        }
    }
```

- `f[0]=1` 是方案数的初值：凑出 $0$ 元有 $1$ 种（什么都不选）。
- 外层枚举硬币种类、内层**正序**枚举价值，这正是完全背包的写法——每种硬币可以用无限次。
- `if(j-c[i]>=0)` 防止越界，也可以把循环起点改成 `j=c[i]`。
- 这一步只与面值有关，与询问无关，所以放在读入询问之前做一次。

### 逐次询问 + 容斥

```cpp
    while(n--){
        for(int i=0;i<4;i++) cin>>d[i];
        int s;cin>>s;
        int ans=0;
        for(int i=0;i<16;i++){
            int cnt=s,res=0;
            for(int j=0;j<4;j++){
                if(i&(1<<j)) cnt-=(d[j]+1)*c[j];
            }
            if(cnt>=0) res=f[cnt];
            if(__builtin_popcountll(i)&1) ans-=res;
            else ans+=res;
        }
        cout<<ans<<'\n';
    }
    return 0;
}
```

- `for(int i=0;i<16;i++)` 枚举 $2^4=16$ 个集合，第 $j$ 位为 $1$ 表示「第 $j$ 种硬币超限」。
- `cnt-=(d[j]+1)*c[j]`：把超限的那部分先扣掉，剩下的价值交给无上限背包。
- `if(cnt>=0) res=f[cnt];`：扣成负数说明这种组合不可能，贡献为 $0$。
- `__builtin_popcountll(i)&1` 判断集合大小的奇偶：奇数个超限就减，偶数个就加——这就是容斥的「偶加奇减」。
- 内层 `for` 结束后直接输出 `ans`，多组询问互不影响。

## 复杂度分析

完全背包预处理是 $O(4N)$；每次询问枚举 $16$ 个集合、每个集合扫 $4$ 种硬币，是常数 $64$，所以 $n$ 次询问总共 $O(16n)$。合计 $O(16n+s)$ 量级，空间 $O(s)$。

## 常见陷阱与注意事项

- **超限要减 `d[j]+1` 而不是 `d[j]`**：超出上限至少要买 $d_j+1$ 枚，写成 $d_j$ 会把「刚好用满」的情况错误地算进补集。
- **扣成负数要判掉**：`cnt<0` 时 $f[cnt]$ 是越界访问，必须先判 `cnt>=0`。
- **多组询问别重建背包**：`f` 只与面值有关，重建会多出 $n$ 倍的常数。
- **容斥符号**：奇数次超限减、偶数次加，写反会得到负数或者答案翻倍。
- **`#define int long long` 与 `main`**：必须写 `signed main`，否则编译报错。
- **数组上界**：$s\le10^5$，`N` 开小了会越界读。

## 对比与扩展

- 与「P3758 可乐」的关系：那道题用矩阵把时间维压掉，本题用容斥把「上限」这个约束压掉，都是「换一种表示让问题变简单」。
- 如果硬币种类从 $4$ 增加到 $k$，容斥部分会退化成 $O(2^k n)$，$k$ 一大就不能这么做了。
- 这类「带上限的完全背包计数」是容斥的经典模型，和「隔板法 + 上限」是同一类思路。

## 题目描述

给定一个长度为 $n$ 的字符串，由 `(`、`)`、`*`、`?` 组成，其中 `?` 可以替换成任意字符。定义“符合规范的超级括号序列”，规则如下：

1. `()` 和 `(S)` 是合法序列，其中 `S` 是长度不超过 $k$ 的连续 `*` 串；
2. 如果 `A` 和 `B` 合法，则 `AB` 和 `ASB` 合法；
3. 如果 `A` 合法，则 `(A)`、`(SA)`、`(AS)` 合法。

求将所有 `?` 确定后，能得到多少个合法序列，对 $10^9+7$ 取模。

## 解题思路

### 一、为什么是区间 DP

合法括号序列的本质只有两种操作：**嵌套**（把一段合法内容用一对括号包起来）与**拼接**（把两段合法内容接起来）。这两种操作都作用在**一段连续区间**上，天然适合设 $dp[l][r]$ 表示子串 $s[l..r]$ 的方案数，按区间长度从小到大枚举，再枚举分割点合并左右两半。

### 二、只开两维会重复计数

直接写 $dp[l][r]$ 会遇到一个致命问题：**同一个合法序列可能有多种“最后一次拼接”的方式**。

例如 `()()` 既可以看成 `()` 接 `()`，也可以被描述成“左半是以括号序列开头、右半是括号序列”的某种组合；`(())` 既可以看成被括号整体包裹，也符合某种拼接的描述。不区分结构，同一个序列就会被多条转移路径各算一遍。

### 三、关键性质：按“形态”给序列打标签

解决办法是把合法序列按**左右两端的形态**分类，每一类只留**唯一**的转移入口，保证不重不漏。题解把每个区间拆成 **6 种形态** ~~（夺少？）~~，分别用 $dp[l][r][0..5]$ 表示：

| 状态 | 形态描述 | 示例（$k$ 足够大） |
|:---:|------|------|
| `0` | 全部由 `*` 组成 | `***` |
| `1` | 左右直接被一对括号包裹，且内部是合法内容 | `(())`、`(*())` |
| `2` | 左边以括号序列开头，右边以 `*` 结尾 | `()**`、`(**)*` |
| `3` | 左边以括号序列开头，右边以括号序列结尾（包含状态 1） | `()()`、`(())` |
| `4` | 左边以 `*` 开头，右边以括号序列结尾 | `**()`、`*(*)` |
| `5` | 左边以 `*` 开头，右边以 `*` 结尾（包含状态 0） | `***`、`**()*` |

两个包含关系必须记住：

- **状态 1 是状态 3 的子集**，代码里每轮结束后做 `h[l][r] += b[l][r]`，把状态 1 并入状态 3；
- **状态 0 是状态 5 的子集**，代码里做 `tr[l][r] += sr[l][r]`，把状态 0 并入状态 5。

### 四、为什么要拆这么多状态

区间 DP 的去重是本题最大的难点。形态拆分本质上是给每个合法序列打一个“标签”，这个标签决定了它**下一步能参与哪种拼接**。

1 和 3、0 和 5 虽然在最终统计里都会被算进答案，但在**转移过程中**它们扮演的角色完全不同：状态 2 只能“左边取状态 3、右边接全 `*`”，状态 4 只能“左边取状态 4 或 5、右边接状态 1”。不分开存，就会走错转移或者重复累加。分开存、最后再并入，是“先各自记账、最后汇总”的典型写法。

### 五、两个基础预处理

- `sr[l][r]`：区间 $[l,r]$ 能否全部填成 `*`，且长度不超过 $k$。递推是 `sr[l][r] = sr[l][r-1] && (s[r]=='*' || s[r]=='?')`，并且只在 `len<=k` 时允许成立。
- `cmk(l,r)`：$l$ 与 $r$ 能否配成一对括号，即 `s[l]` 是 `(` 或 `?`、且 `s[r]` 是 `)` 或 `?`。

空区间视为“可以全填成 `*`”，代码用 `sr[i][i-1]=1` 初始化，这样 `()` 这种内部为空的情况也能被正确计数。

### 六、六类转移

代码里 `sr / b / f / h / c / tr` 依次对应状态 0~5。

- **状态 0（`sr[l][r]`）**：只在 `len<=k` 且末尾能填 `*` 时成立。
- **状态 1（`b[l][r]`）**：当 `cmk(l,r)` 成立，内部可以是全 `*`、状态 2/3/4：

$$b[l][r]=sr[l+1][r-1]+f[l+1][r-1]+h[l+1][r-1]+c[l+1][r-1]$$

- **状态 2（`f[l][r]`）**：左边取状态 3、右边接全 `*`：

$$f[l][r]\mathrel{+}=h[l][i]\cdot sr[i+1][r]$$

- **状态 3（`h[l][r]`）**：一是状态 1 直接并入；二是左边取状态 2 或 3、右边接一个状态 1：

$$h[l][r]\mathrel{+}=\left(f[l][i]+h[l][i]\right)\cdot b[i+1][r]$$

- **状态 4（`c[l][r]`）**：左边取状态 4 或 5、右边接一个状态 1：

$$c[l][r]\mathrel{+}=\left(c[l][i]+tr[l][i]\right)\cdot b[i+1][r]$$

- **状态 5（`tr[l][r]`）**：一是状态 0 直接并入；二是左边取状态 4、右边接全 `*`：

$$tr[l][r]\mathrel{+}=c[l][i]\cdot sr[i+1][r]$$

上面所有累加都在模 $10^9+7$ 意义下进行。

### 七、为什么这样不重不漏

每种形态都规定了该序列下一步**唯一**的拼接方式：状态 2 只能向右再接一段 `*`、状态 4 只能向右再接一个被括号包裹的块，如此类推。因此任意合法序列在生成过程中只会经过一条固定的状态链，不会被两条路径同时算到。

又因为合法序列首尾必然是括号（不可能是 `*`），所以整串一定落在“左括号序列、右括号序列”的状态 3 上，答案就是 `h[1][n]`。

### 八、复杂度

- 状态数 $O(6n^2)$，每个状态转移枚举分割点 $O(n)$；
- 总复杂度 $O(n^3)$，$n\le 500$ 时期望得分 100。

## 逐行代码解析

### 全局定义与括号配对函数

```cpp
#include<bits/stdc++.h>
#define endl '\n'
#define fi first
#define se second
#define lowbit(x) (x&(-x))
#define int long long
using namespace std;
typedef pair<int,int> PII;
typedef long long ll;
const int N=510,mod=1e9+7;
int cnt=0,n,k;
string s;
int sr[N][N],b[N][N],f[N][N],h[N][N],c[N][N],tr[N][N];
bool cmk(int l,int r){
	if((s[l]=='('||s[l]=='?')&&(s[r]==')'||s[r]=='?')) return true;
	else return false;
}
```

- `#define int long long` 把全程序的 `int` 提升为 64 位，转移里两个模数量级相乘不会溢出。
- 六个二维数组 `sr / b / f / h / c / tr` 一一对应状态 0~5；`N=510` 保证 $n\le 500$ 时不越界。
- `cmk(l,r)` 判断左右端点能否配成一对括号：左端是 `(` 或 `?`、右端是 `)` 或 `?`。只有它成立时才去算状态 1。
- `cnt`、`PII`、`fi/se/lowbit` 是模板残留，本题没有用到，不影响正确性。

### main（二）：区间 DP 主循环

```cpp
	for(int len=1;len<=n;len++){
		for(int l=1;l<=n-len+1;l++){
			int r=l+len-1;
            //if(len<=k&&sr[l+1][r]==1&&(s[l]=='*'||s[l]=='?')) sr[l][r]=1;
			if(len<=k&&sr[l][r-1]==1&&(s[r]=='*'||s[r]=='?')) sr[l][r]=1;
			if(len>=2){
                bool u=cmk(l,r);
                //cout<<u<<" "<<l<<" "<<r<<"\n";
                if(u) b[l][r]=(sr[l+1][r-1]%mod+f[l+1][r-1]%mod+h[l+1][r-1]%mod+c[l+1][r-1]%mod)%mod;
			    for(int i=l;i<r;i++){
				    f[l][r]=(f[l][r]%mod+h[l][i]*sr[i+1][r]%mod)%mod;
				    h[l][r]=(h[l][r]%mod+(f[l][i]+h[l][i])*b[i+1][r]%mod)%mod;
    				c[l][r]=(c[l][r]%mod+(c[l][i]+tr[l][i])*b[i+1][r]%mod)%mod;
				    tr[l][r]=(tr[l][r]%mod+c[l][i]*sr[i+1][r]%mod)%mod;
    			}
            }
            h[l][r]=(h[l][r]%mod+b[l][r]%mod)%mod;
			tr[l][r]=(tr[l][r]%mod+sr[l][r]%mod)%mod;
		}
    }
```

- 外层按区间长度递增、内层枚举左端点，保证转移用到的更短区间都已算完。
- `sr[l][r]` 只在 `len<=k` 时递推，落实“`*` 段长度不超过 $k$”。
- `b[l][r]` 是状态 1；`f/h/c/tr` 在同一轮里按四条转移方程累加，其中 `h` 用到的 `h[l][i]` 是更短区间，不会读到本轮刚写的值。
- **状态并入必须放在分割点循环之后**：`h += b`、`tr += sr` 都写在 `if(len>=2)` 块外面，保证本轮转移全程用的是“未并入”的旧值；如果提前并入，会污染同一轮的后续转移，造成重复计数。

## 复杂度分析

- **时间**：区间共 $O(n^2)$ 个，每个区间维护 6 个形态，转移时枚举分割点 $i$ 花 $O(n)$，总计 $O(n^3)$。$n=500$ 时约为 $1.25\times 10^8$ 次基本运算，常数很小（都是加乘取模），可以接受。
- **空间**：六个 $N\times N$ 的数组。因为 `#define int long long`，每个元素 8 字节，$6\times 510\times 510\times 8 \approx 12.5$ MB；加上字符串与杂项，$O(n^2)$ 空间。

## 常见陷阱与注意事项

1. **重复计数的根源**：不区分形态时，`(())` 会同时被“括号包裹”和“拼接”两条路径算到；状态 1 与 3、状态 0 与 5 必须分开存、最后再并。

2. **状态并入的时机不能提前**：`h += b` 与 `tr += sr` 必须放在分割点循环结束之后，否则同一轮后续转移会读到已经并入的值。

3. **空区间的边界**：`sr[i][i-1]=1` 处理了 `()` 内部为空的情况；漏掉它，`()` 与 `(*)` 都会少算。

4. **`len>=2` 的判断**：长度为 $1$ 的区间不可能是括号序列，代码用 `if(len>=2)` 跳过 `b/f/h/c/tr` 的计算；但 `sr` 的递推和最后的并入仍要照常执行。

5. **`#define int long long` 的必要性**：转移里出现 `(f[l][i]+h[l][i])*b[i+1][r]`，两个模数量级相乘接近 $10^{18}$，32 位 `int` 会溢出；同时主函数必须写 `signed main`。

6. **下标从 1 开始**：靠 `s=' '+s` 补空格实现，避免每个转移都写一遍边界特判。

7. **答案取状态 3 的原因**：合法序列首尾必然是括号，因此一定属于“左括号序列、右括号序列”这一形态。

8. **`sr` 的语义容易被误读**：`sr[l][r]` 为真只表示“这段能全部填成 `*`”，`?` 在其中被当作 `*`；`?` 填成括号的情况由其它状态单独计数，二者不冲突。

## 对比与扩展

| 做法 | 时间 | 空间 | 说明 |
|---|---|---|---|
| 六状态区间 DP（本题） | $O(n^3)$ | $O(n^2)$ | 用形态标签去重，$n\le 500$ 可过 |
| 朴素两维区间 DP | $O(n^3)$ | $O(n^2)$ | 不区分形态，合并时重复计数，结果偏大 |
| 记忆化搜索 | $O(n^3)$ | $O(n^2)$ | 思路相同，去重仍然需要同样的状态拆分 |

- 本题“按首尾形态拆分状态”是区间 DP 计数去重的通用套路，可以迁移到括号着色计数、表达式拆分计数等区间计数问题。
- 若去掉 $k$ 的限制（`*` 段长度任意），状态 0 与 5 会退化成普通的前缀判断，整体框架不变。
- 与括号树（P5658）等题一样，核心都是“合法括号序列可由嵌套与拼接唯一分解”这条性质；区别在于本题要**计数**，因此必须额外解决“同一序列被多种分解方式统计”的去重问题。
